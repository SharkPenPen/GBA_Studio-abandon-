> 素材：`D:\游戏解包\Nightmare×sisters～淫狱的献祭～\剧本\台词对照_JP_CN.tsv`
> 工具：`tools/tsv_to_project.py`
> 结论：**整部剧本 + 字库只占卡带的 1.5%**，中文在实机上渲染正常 ✅
>
> 这套素材来自一部 18+ 作品。本文只记录**技术过程与数字**，
> 不涉及、不转述任何台词内容；工具本身也只做机械转换。

## 一、结论先放前面

**这是整条移植路上最划算的一步。** 5705 句台词全部搬上去，只花了：

| 项目 | 大小 | 占 32MB 卡带 |
|---|---|---|
| 剧本（5752 条命令） | 约 221 KB 文本 | 0.7% |
| 中文字库（2052 字） | **53 KB** | 0.2% |

**实测验证**：抓帧后对话框区域有 **4924 个文字像素** ✓ 中文正常渲染 ✓
（整帧只有 6 种颜色 = 纯文字画面，符合"还没有美术素材"的状态）

**这意味着**：文字从来不是瓶颈 ✗ 一个视觉小说能不能移植，
瓶颈在**语音**（见 [17-移植可行性评估.md](17-移植可行性评估.md)）✗ 不在文字 ✓

## 二、为什么不需要啃 `.ws2` 二进制

解包工具已经产出了一张**双语对照表** `台词对照_JP_CN.tsv`：

```
场景      索引   日文                                中文
s0_01     0      char「除霊を終えて…%K%P」           除灵结束，我和姐姐一起泡澡。%K%P
s0_01     1      char「湯船に熱いお湯を…%K%P」       浴缸里注满热水，浸到脖子。%K%P
```

它已经有**场景名 + 行号 + 中文** ✓ 正好是一个视觉小说需要的全部信息 ✓
所以转换器**直接吃这张表** ✓ 不用去解析 511 个 `.ws2` 的二进制 ✓

（`.ws2` 里还有**背景切换、立绘显隐、语音编号**等信息 ✗
 那些要等第二阶段：解析 `.ws2` 或 Lua ✓ 才能自动补上 ✓
 现在是"文字全有、画面全无"的状态 ✓ 但**已经能完整读下来** ✓）

## 三、转换器做了什么

### 1. 清控制码

原作的文本里混着控制码 ✓ 每个都要处理对 ✓：

| 控制码 | 含义 | 处理 |
|---|---|---|
| `%K` | 等待按键 | **去掉**（引擎的 `say` 本身就是等玩家） |
| `%P` | 翻页 | **去掉**（我们自己按 3 行分页） |
| `\n` | 原作手动换行 | **换成空格**（引擎自己会排版，留着会双重换行） |
| `「」` | 对话引号 | **去掉**（外层包装） |

### 2. 分页 —— 这一步最容易出错

引擎的对话框**写死 3 行**（`TEXT_LINES 3`）✗ 而原作一页经常超过 3 行 ✓
不分页的话，超出的部分在实机上**直接消失，而且不报任何错** ✗

所以转换器用 `core.preview.layout_text` ✓ —— 那是**照引擎一字不差重写的排版算法** ✓
先算出这句要几行，超过 3 行就切成多页 ✓
**编辑器里看到的换行 = 实机上的换行** ✓

> ⚠ 这里有个坑，被测试抓出来了：
> `layout_text` 的默认参数是 **`max_lines=TEXT_LINES`（=3）** ✗
> 它是给**渲染**用的，排满 3 行就停 ✓
> 拿默认值来分页，永远只看到 3 行 ✓ 于是"每句都刚好 3 行" ✓
> **分页根本没生效** ✗ 必须传 `max_lines=9999` 才能拿到全部行 ✓

### 3. 输出

```
<out>/Nightmare移植/Nightmare移植.gbastudio
   45 个场景（每个 TSV 场景 → 一个 story 场景）
   5705 个 text 片段（每页一个）
```

在编辑器里打开就能改台词、加立绘、挂语音 ✓ 导出时字库自动生成 ✓

## 四、实测数字

```
输入：台词对照_JP_CN.tsv
      5705 行 / 45 个场景（另有 511 个 .ws2，但只有 45 个含台词）

转换：45 场景 / 5705 页
      中文 113,062 字，其中【1948 个不同字】
      字库需求 ≈ 48 KB
      文本需求 ≈ 221 KB

字库生成（自动）：
      字符集共 2052 个字符（含 ASCII 与界面文字）
      font_glyphs.bin   45,144 字节（2052 字 × 11×11）
      font_index.bin     8,208 字节
      → 53 KB

ROM（纯文本工程，0 图 0 音频）：
      507,740 字节 = 495.8 KB = 卡带的 1.5%
      编译用时 3.6 秒
      ✅ 抓帧验证：对话框 4924 个文字像素 → 中文渲染正常
```

**字库为什么只有 2052 字**（而不是通常说的 3500+）✗
因为这是**翻译过的剧本** ✓ 用字范围比原创中文窄 ✓
而且字库是**按剧本实际用到的字自动生成**的 ✗ 一个不多一个不少 ✓

## 五、这一步顺带修掉的 5 个 bug

这些都不是"功能没做"，而是**"某些输入下会静默出错"** ✗ 最值得修的一类：

### 1. 长台词被静默截断（测试抓到的）

`layout_text(text)` 默认只排 3 行 ✓ 分页逻辑因此完全失效 ✓
**表现**：实机上后半句直接不见，没有任何报错 ✗
**修**：`layout_text(text, max_lines=9999)` ✓

### 2. 一张图都没有的工程 → 链接失败

```
error: undefined reference to `anim_defs' / `anim_durs' / `gfx_logo_asset'
```

`make_project_assets.py` 在"清单里没有素材"时 `return 1` ✓
→ `build-assets.ps1` 抛错 → **后面 3 步（音频/关卡/动画）全都不跑** ✓
→ 生成器没产出符号 → 链接期一堆 undefined ✗

**而"新建的工程"正好就是一张图都没有** ✗ 所以这个坑**一定会踩到** ✓
**修**：空素材时照常往下走，产出**空表** ✓（引擎本来就是按"表长可能是 0"写的 ✓）

### 3. `.ps1` 丢了 UTF-8 BOM（这个项目的老毛病，今天又踩）

编辑 `build-assets.ps1` 时 BOM 没了 ✗
PowerShell 5.1 没有 BOM 就**按 GBK 读** ✓ 中文全变乱码 ✓
报的却是莫名其妙的语法错：
```
Array index expression is missing or not valid.
```
——**完全看不出是编码问题**，能查半天 ✗
**修**：补回 BOM ✓ 并加测试 `test_ps1_files_have_utf8_bom` 永久守住 ✓

### 4. `source/assets` 里的陈旧文件不会被清理

做实验留下的 `probe_bg.bin` 一直躺在那里 ✓ 而且**会被一起编进 ROM** ✗
**修**：`build-assets.ps1` 每次生成前先清掉生成物 ✓

### 5. 产物缺失没有自检

上面第 2 条之所以难查，是因为"某一步悄悄没产出"要到**链接期**才暴露 ✗
**修**：脚本末尾自检 9 个关键产物在不在 ✓ 缺了就明确报出来 ✓
（这次实测：`产物自检通过（9 个关键文件都在）`）
