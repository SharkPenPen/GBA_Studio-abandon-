## 2. 实测明细

### 2.1 安装

```
python -m pip install PySide6 -i https://pypi.tuna.tsinghua.edu.cn/simple
→ PySide6 6.12.0 + PySide6-Essentials + PySide6-Addons + shiboken6
```

安装后占用 **647 MB**，其中**用不到的部分**：

| 组件 | 体积 | 说明 |
|---|---|---|
| `Qt6WebEngineCore.dll` | **194 MB** | 浏览器内核，完全用不到 |
| `Qt6Pdf.dll` | 4 MB | 用不到 |
| `Qt6Quick3D.dll` / `Qt6Charts.dll` | 3 MB | 用不到 |

**打包时用 `--exclude-module` 排掉，能省 200 MB 左右。**
（不打包则无所谓，反正硬盘够。）

### 2.2 可用的 Qt 模块（实测 import 成功）

| 模块 | 用途 |
|---|---|
| `QtWidgets` | 主窗口、停靠面板、表格、树、对话框 |
| `QtGui` / `QtCore` | 图像、字体、场景图、撤销栈、定时器 |
| `QtMultimedia` | **预览试听 BGM/语音**（Tkinter 做不到这点） |
| `QtSvg` | 图标 |
| `QtOpenGLWidgets` | 以后要硬件加速渲染时用 |
| `QtNetwork` | 以后要做"分享/更新"时用 |

### 2.3 启动速度（重要修正）

| 场景 | 实测 |
|---|---|
| 导入 Qt | 100 ms |
| 建 QApplication | 24 ms |
| **开发模式总启动** | **157 ms** |

**我之前说的"Qt 版启动 3~5 秒"是错的** —— 那个数字来自 **PyInstaller 单文件解包**，
和 Qt 本身无关。

- **日常使用**：直接 `python gbastudio\main.py` → **0.16 秒启动**，不打包、不占额外空间 ✅
- **只有要分发给别人时**才需要打包成 exe（那时才面对大体积和慢启动）

这消除了方案 A 最大的一个顾虑。

## 3. 风险清单与对策（都已想好）

| # | 风险 | 实情 | 对策 |
|---|---|---|---|
| 1 | 打包体积大 | 装完 647 MB，含 194 MB 用不到的 WebEngine | 打包时 `--exclude-module PySide6.QtWebEngine*` 等 → 预计 exe 100~150 MB |
| 2 | 单文件 exe 启动慢 + 临时目录坑 | 这是 **PyInstaller 解包** 的问题，本机还踩过 `%TEMP%` 权限坑 | ①日常**不打包**（0.16 秒）②要分发就用 `--runtime-tmpdir` 指向工程内（`GBAStudio.exe` 上已验证过这个修法）③或用"文件夹版" |
| 3 | 大图块地图性能 | 256×256 图块 = 6.5 万个图元，逐个 `QGraphicsItem` 会卡 | **把可视区域的图块渲染成一张 QImage 再贴**（图块编辑器标准做法）✅ |
| 4 | 预览帧率 | 240×160 只有 38,400 像素 | Qt 毫无压力；实测静态画面已正常，动态只需换 QPixmap |
| 5 | 预览与实机不一致 | Python 版渲染是第二套实现 | 已规划**自动化像素比对**：同一段剧情，一边截 mGBA 画面、一边截预览画面，逐像素 diff（截图工具链已有）|
| 6 | 与现有 C 引擎衔接 | 编辑器只产出数据 + 调 `build.ps1` | 完全不变，无需改动现有管线 ✅ |
| 7 | 引擎地基（模式 3 天花板） | 做不了动作/RPG（无硬件精灵、无图块滚动） | 单独排期为 **P5：升级到模式 0/1 + 硬件 OBJ**（C 侧，与编辑器解耦）|
| 8 | 版权（分发时） | PySide6 是 LGPL | 自己用无碍；将来分发时按 LGPL 要求动态链接即可（PyInstaller 方案符合）|

## 5. 新编辑器的架构（gbastudio）

```
gbastudio/
  main.py                入口（0.16 秒启动）
  core/
    project.py           项目数据模型（通用：场景 / 对象 / 层 / 图块 / 精灵 / 事件）
    assets.py            资源库：导入、缩略图、**GBA 合规检查**
    compiler.py          事件表 → pack.bin；调用 build.ps1
    preview.py           Python 版 240×160 渲染 + QtMultimedia 试听
  modes/
    base.py              模式接口（build_ui / on_activate / on_save）
    story.py             剧情模式（时间轴）★ 第一个做
    level.py             关卡模式（图块）  ← 验证"多模式架构"真的成立
    sprite.py            精灵/动画模式
    logic.py             逻辑模式（事件表）
  ui/
    mainwindow.py        主窗口 + 停靠 + **模式切换条**
    timeline.py          时间轴画布
    tilemap.py           图块画布
    inspector.py         属性（由数据类型自动生成控件）
    preview_panel.py     预览面板
```

### 关键设计：模式注册表

和现有节点编辑器里"节点类型注册表"同一个套路（那次证明有效）：

```python
MODES = [StoryMode, LevelMode, SpriteMode, LogicMode]
```

- 主窗口读这张表，**自动生成模式切换按钮和菜单**
- 加一个新游戏类型 = 加一个 `Mode` 子类，不用改主窗口
- 每个模式只管自己的画布和属性，共享"项目/资源/预览/编译"这些通用能力

### 数据模型要"通用设计、按需实现"

这是**唯一不能省**的事：项目的场景/对象/层/资源结构按通用设计，
但当前只实现剧情模式用到的那部分。这样将来加关卡模式时，
不用推倒已有作品。
