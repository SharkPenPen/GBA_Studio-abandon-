# 全量试装：整部作品进 32MB 卡带会怎样

> 素材：`D:\游戏解包\Nightmare×sisters～淫狱的献祭～`
> 工具：`tools/tsv_to_project.py`（剧本）+ `tools/collect_assets.py`（素材）
> 结果：**25.19 MB / 32 MB（78.7%）** —— 装得下 ✅ 而且画面和声音都在 ✅
>
> 这是从一部 18+ 作品解包的素材。本文只记录**技术与容量数据**，
> 不涉及、不转述任何内容；工具只做机械转换。

## 一、结论

**把能塞的都塞进去，ROM 是 25.19 MB —— 刚好装进 32 MB 卡带。**

| 装进去的东西 | 数量 | 占用 |
|---|---|---|
| 中文台词 | **5705 句全部** | 约 0.5 MB（含 2052 字字库） |
| 背景 / 事件 CG | 45 张 | 3.4 MB |
| 立绘 | 6 个 | （含在上面 3.4 MB 里） |
| **语音** | **180 条（12%）** | 约 13 MB |
| BGM | 45 首 | 约 8 MB |
| 音效 | 15 个 | 约 0.3 MB |
| **ROM 实测** | | **25.19 MB = 卡带 78.7%** |

**实测验证**：抓帧后整帧 **1712 种颜色** ✓
（对比：纯文字版本只有 6 种颜色 ✓ 说明背景图确实画在画面上了 ✓）
对话框 **4924 个文字像素** ✓ 中文渲染正常 ✓

**一句话**：**文字和画面能全搬，语音只能搬一成。**
这不是估算，是真编出来的 ROM 量的 ✓

## 二、素材分类：目录名不可信，文件名才可信

这一步花了不少功夫 ✗ 因为**解包时是按封包分目录的**（`Chip1..6`）✓
所以目录名和内容对不上 ✗

**实测发现**：

```
立绘/            ← 名字叫"立绘"，但里面是 BG / EV / 特效遮罩，一张角色立绘都没有 ✗
PNG输出/ST##X_Y/ ← 角色立绘在这里（12 个目录）★
PNG输出/EV*/     ← 事件 CG（369 个目录）★
立绘/Chip3/BG*.PNG ← 真正的背景在这里（57 张）
```

**全库文件名前缀统计（4170 个 png）**：

| 前缀 | 数量 | 是什么 | 处理 |
|---|---|---|---|
| `FRAME_` | 3529 | 角色差分帧 | 取同目录的 `_composed.png`（完整立绘） |
| `EV` | 488 | 事件 CG | 当背景收（每目录取一张） |
| `BG` | 57 | 背景 | 直接收 |
| `ST` | 12 | 角色 ID | 建角色表 |
| `SYS_*` | 40+ | 界面图 | 暂不要（做菜单时再说） |
| `EFMSK_`/`LAYERMASK_`/`EST_` | 36 | 特效遮罩 | 不要（GBA 用不上） |

**角色立绘的正确取法**：每个 `ST##X_Y` 目录里有一张 `ST##X_Y_composed.png`
= **拼好的完整立绘** ✗ 那些 `frame_001..020.png` 是**差分帧** ✓
（帧尺寸五花八门：363×963、715×1106、181×180 ✓ 不能直接当立绘用 ✗）

实测拿到 **12 个角色**（`ST01A_L` … `ST05_M`）✓ 和 NameTable 里的 ID 对得上 ✓

## 三、一个重要的机制：编译器只打包"被引用"的素材

第一遍导出时，清单是 **`bg=0 sprites=0 audio=0`** ✗
明明是 432 个素材的工程 ✓

**原因**：编译器**只把被片段引用到的素材打进 ROM** ✓
而转换器建的是**纯文字片段** ✗ 没引用任何图/音 ✓

**这正好说明缺的是什么** ✓✓：
「哪一句切哪张背景、显哪个立绘、放哪条语音」——**这个信息在 `.ws2` 字节码里** ✗
拿到它才能自动补上 ✓

为了让容量账量得准 ✓ 加了一个 **`--fill` 演示填充** ✓：
把背景/立绘/语音**轮着**挂到场景上（**合成**的挂法 ✓ 不是原作调度 ✓）
只为回答"装满是什么样" ✓

## 四、卡在哪：`.ws2` 是字节码，需要操作码表

我做了完整的探测 ✓ 结论明确：

```
s0_01.ws2  10541 字节
  按 UTF-16LE 解 → 不是文本 ✗
  找已知消息索引序列（0,1,2,… 各种编码、各种 base）→ 一个都找不到 ✗
  字节分布：0x00 占 2483、0x0A 占 1516、不同值 236 种
  高位置 1 的字节 27.9%
  → **结构化**（不是加密，加密会接近均匀分布）
  → 有重复的 12 字节记录（命令格式）
  → 是**字节码 VM 程序**，操作码没有文档 ✗
```

**完整逆向是几天的活，而且收益不确定** ✗

**但有更快的路** ✗✓：**你的解包工具已经解析了 505/511 个文件** ✓
报告里甚至点名了 6 个未知操作码（`0xF9~0xFE`）✓
→ **那份操作码表能把这件事从几天变成一小时** ✓✓

**我需要的就是它** ✓ 有下面任一样都行：
- 操作码表（`0x00`~`0xFF` 各是什么命令、参数几个字节、怎么编码）
- 或者你那个 `.ws2` 解析器的源码（哪一段都行，能看出结构就够）
- 或者**解析后的文本输出**（比如"`bg 12` / `char 0 1` / `mes 45`"这种每行一条的中间格式）

有了它，我就能把「背景切换 + 立绘显隐 + 语音编号」自动补进 45 个场景 ✓
那之后这个移植就**基本成型**了 ✓
