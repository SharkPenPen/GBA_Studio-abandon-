# 分章分盘：3 盘卡带能装多少

> 工具：`tools/build_chapters.py`（一键分章构建）
> 结果：**3 个独立 ROM，共 73.91 MB，背景覆盖 93%、语音覆盖 36%**
>
> 这是从一部 18+ 作品解包的素材。本文只记录**技术与容量数据**，
> 不涉及、不转述任何内容；工具只做机械转换。

---

## 一、核心思路

**32 MB 是每盘卡带的限制，不是"整个游戏"的限制。**

所以把作品按章节切开 ✓ 每章做一盘独立的卡带 ✓
于是可装的东西**按盘数成倍增加** ✓

原作的场景编号天然就是分章的 ✓（`s0_01` / `s1_03` / `s2_07` ✓）：

| 章节 | 场景数 | 台词页 | 中文字数 | 字库 |
|---|---|---|---|---|
| **s0** | 25 | 3099 | 85,934 | 42 KB |
| **s1** | 5 | 579 | 16,056 | 24 KB |
| **s2** | 15 | 2027 | 46,227 | 35 KB |
| 合计 | 45 | 5705 | 148,217 | 48 KB（合并时） |

---

## 二、实测结果（3 个 ROM 真的编出来了）

| 章节 | ROM 大小 | 占卡带 | 场景 | 台词页 | 背景 | 音频 |
|---|---|---|---|---|---|---|
| **s0** | 24.28 MB | 75.9% | 25 | 3099 | 125 | 184 |
| **s1** | 24.75 MB | 77.4% | 5 | 579 | 140 | 190 |
| **s2** | 24.87 MB | 77.7% | 15 | 2027 | 135 | 193 |
| **合计** | **73.91 MB** | — | 45 | 5705 | **400** | **567** |

**验证**：跑 s1 抓帧 ✓ 整帧 **1762 种颜色** ✓（纯文字版只有 6 种 ✓ 说明背景图在画面上 ✓）
对话框 **4924 个文字像素** ✓ 中文渲染正常 ✓

## 三、和"单盘塞完"对比

| | 单盘塞完（1 个工程） | **分 3 章（3 盘）** | 提升 |
|---|---|---|---|
| 中文台词 | 5705 页（100%） | 5705 页（100%） | — |
| **背景 / CG** | 150 / 429 = **35%** | **400 / 429 = 93%** | **2.7×** |
| **语音** | 180 / 1488 = **12%** | **541 / 1488 = 36%** | **3.0×** |
| 立绘 | 12 个 | 12 个 | — |
| BGM | 10 首 | 10 首（分摊到 3 盘） | — |
| 音效 | 60 / 187 = 32% | 180 / 187 = 96% | 3.0× |
| **卡带占用** | 1 盘（25.19 MB） | **3 盘（73.91 MB）** | — |

**一句话**：花 3 倍卡带容量 ✗ 换来**背景几乎全搬、语音从一成提到三成半** ✓

## 四、容量怎么算的（都是实测值）

```
卡带 32 MB，留 5 MB 余量                → 预算 27 MB
引擎 + 剧本 + 字库                       → 约 0.8 MB
背景  75.0 KB/张（240x160 16bpp 实测）
立绘  50.0 KB/张（缩到 120px 高实测）
音频  11.0 KB/秒（8bit 单声道 11025Hz 实测）
      BGM 约 85 秒/首 ≈ 935 KB
      语音 约 6 秒/条  ≈ 66 KB

每盘：27 − 0.8 − 11.1（143 张背景 + 12 立绘）= 15.2 MB 给音频
      → 先分 25% 给 BGM（3~4 首），剩下的全给语音
      → 约 170~190 条语音
```

**语音是唯一的大头** ✗ 图像再多也只是 11 MB 左右 ✓
所以"分盘"这个操作，**收益几乎全部落在语音上** ✓

## 五、还能再提吗？

现在的瓶颈是**每盘 11 MB 的背景** ✓ 而这 11 MB 里有 **93% 用在了"这一章可能根本用不到"的图上** ✗

**如果拿到 `.ws2` 的操作码表** ✓（见 [19-全量试装实测.md](19-全量试装实测.md) 第四节）：
- 每章只装**这一章真正用到的**背景 ✓ 而不是"整库的三分之一"
- s1 只有 5 个场景 ✓ 可能只需要 20~30 张图 ✓ → 省下的 9 MB 全给语音
- **那样语音覆盖率能到 70~80%** ✓✓

**再加上：**
- 降采样率（11025 → 7884 Hz）能省 28% ✗ 语音会明显发闷 ✓
- 语音只留关键句（每章开场 + 名场面）✓ 听感反而更好 ✓

## 六、怎么用

```powershell
# 一键分章构建（3 章 → 3 个 ROM）
python tools\build_chapters.py `
    --src  "D:\游戏解包\Nightmare×sisters～淫狱的献祭～" `
    --tsv  "D:\游戏解包\Nightmare×sisters～淫狱的献祭～\剧本\台词对照_JP_CN.tsv" `
    --chapters s0,s1,s2

# 产出：nxs_s0.gba / nxs_s1.gba / nxs_s2.gba
# 报告：.tmp\chapters_report.json
```

脚本会**自动备份并还原**引擎仓库里的"当前导出" ✓
（跑完示例工程的构建也帮你恢复好 ✓）

**单独做某一章：**

```powershell
# 剧本（只取 s1 章）
python tools\tsv_to_project.py --tsv "<对照表>" --out "<输出目录>" --name s1 --chapter s1

# 素材（取第 1/3 份，各章不重叠）
python tools\collect_assets.py --src "<解包目录>" --project "<工程>" --share 1/3
```

## 七、结论

1. **分章分盘是有效的** ✓ 背景 35%→93%、语音 12%→36%（各 3 倍左右）✓
2. **文字和立绘本来就装得下** ✗ 分盘对它们没有影响 ✓
3. **语音仍然是最紧的** ✗ 想再提只能靠"每章只装本章素材"（要操作码表）或降采样率
4. **3 盘卡带换 3 倍内容** ✓ 这个交易在 GBA 上很划算 ——
   原作的章节结构本来就是分开的 ✓ 玩家一章一盘也不会觉得奇怪 ✓
