## 1. 三层体系结构

```
┌─ 移植流水线（tools/*.py）──────────────────────────────┐
│  商业游戏解包数据（.ws2 剧本 / PNG / OGG）              │
│      ↓ ws2_scenes.py / ws2_recipes.py （提取真实调度）  │
│      ↓ compose_scenes.py        （多层合成成一张图）     │
│      ↓ tsv_to_project.py        （生成 .gbastudio 工程）│
└───────────────────────┬───────────────────────────────┘
                        ↓ .gbastudio（JSON）
┌─ 编辑器（gbastudio/，PySide6）─────────────────────────┐
│  剧情工作区：时间轴排戏（图层 > 轨道 > 片段）            │
│  关卡工作区：图块地图                                   │
│  精灵工作区：动画帧                                     │
│      ↓ 「导出 GBA」                                     │
└───────────────────────┬───────────────────────────────┘
                        ↓ scenario.txt + assets.json + include/*.h
┌─ 引擎（source/，C + devkitARM）────────────────────────┐
│  vn.c 剧本解释器 → gfx/text/sound/obj/bg/anim/level    │
│      ↓ build.ps1                                        │
└─────────────────────────────────────────────────────────┘
                        ↓
                     xxx.gba（真机/mGBA 可跑）
```

**关键设计决定：合成在 PC 上做，引擎保持简单。**
GBA 的显示模式只给 1~4 个硬件层，而开发者想表达的是"无限图层"。
做法是：**图层数由模式决定（硬件事实，不能增删）**，**每个图层里的轨道随便加**，
**打包时把同一图层里的轨道重叠成一张画面**。
—— 引擎看到的始终是"一张图 + 一句台词"，所以**引擎对这套改动零改动**。

## 2. 引擎（GBA 侧）设计细节

### 2.1 文件分工

| 文件 | 职责 |
|---|---|
| `source/main.c` | 入口、主循环、帧同步（GAL_VBLANK） |
| `source/video.c` | **显示模式注册表**：6 种模式各自的初始化/提交/容量账 |
| `source/gfx.c` | **画布抽象**：`SF_DIRECT`(16bpp) / `SF_INDEXED`(8bpp) / `SF_TILES` |
| `source/text.c` | 字库 + 排版 + 逐字显示（打字机） |
| `source/sound.c` | Direct Sound：语音/BGM 双通道 + 音效 |
| `source/obj.c` | 硬件精灵（`spr_*`） |
| `source/bg.c` | 仿射图层（旋转缩放） |
| `source/anim.c` | 帧动画（`anim_defs` / `anim_durs` 由打包生成） |
| `source/level.c` | 图块关卡（走格子玩法） |
| `source/vn.c` | **剧本解释器**：命令循环 + 对话框 + 立绘状态机 |
| `source/galgame.c` | 顶层状态机：标题 → 剧情 → 关卡 → 结局 |

### 2.2 显示模式（`ui/video_modes.py` 是权威说明）

| 模式 | 硬件图层 | 能做什么 | 容量特点 |
|---|---|---|---|
| 0 | BG0~BG3 四个图块层 + OBJ | **视差/景深/云**（塞尔达那种） | 一层 2 KB 图块地图，四层才 8 KB |
| 1 | BG0 BG1 图块 + BG2 仿射 + OBJ | 视差 + 一层旋转缩放 | 同上 |
| 2 | BG2 BG3 两个仿射 + OBJ | 两层旋转缩放（赛车/飞行） | 同上 |
| 3 | BG2 位图 + OBJ | **32768 色照片级**，任意像素效果 | 一屏 **75 KB**，双缓冲放不下 |
| 4 | BG2 位图（8bpp，可翻页） | 照片级 + 双缓冲 | 同上 / 2 |
| 5 | BG2 位图（160×128） | 小屏 + 快 | 同上 ×0.5 |

**显存总账**：96 KB = BG 64 + OBJ 32 + 调色板 1。
**做游戏前必须先选模式**，因为"能不能做视差"是**硬件决定**的，中途改不了。

### 2.3 剧本命令表（`vn.c` / `scenario.h`）

```
CMD_BG      放背景（索引到素材表）
CMD_SAY     说话（角色 + 文本 + 说话人）
CMD_CHAR    立绘显示/隐藏（位置 left/right/center）
CMD_HIDE    清立绘
CMD_JUMP    场景跳转
CMD_VOICE   语音
CMD_BGM     背景音乐
CMD_BGM_STOP
CMD_SE      音效
CMD_CHOICE  选项分支
CMD_MODE    切玩法模式（剧情 ↔ 关卡）
CMD_END     结束
```

**命令参数全部是索引**（不是文件名）——
所以素材表的顺序由打包决定，改文件不会改剧本。

### 2.4 已知的引擎行为约定（都是"照实机"抠出来的）

- **开局第一帧**：`vn_begin()` 会清台词和说话人（修过一个 bug：以前不清，重玩会闪上一局的最后一句）
- **对话框**：只有"场景里有过内容"才画（空场景不画空框）
- **打字机速度**：`TYPE_SPEED`（每字几帧）
- **跳过标题**：`GAL_SKIP_TITLE`（工程设置 `skip_title`，默认 1 = 直接进剧情）
- **音频初始化**：`snd_init()` 必须在**进剧情之前**调用（踩过：只在标题路径里调，跳过标题就整个没声音）

## 3. 编辑器（PC 侧）设计细节

### 3.1 数据模型（`gbastudio/core/project.py`）

```
Project
 ├ settings      video_mode / skip_title …
 ├ characters    角色表（id / 显示名 / 颜色 / 语音前缀 / 表情）
 ├ assets        素材表（kind: bg/char/sprite/bgm/voice/se）
 ├ level         图块地图
 ├ animations    帧动画
 └ scenes[]
     └ layers[]              图层 ← 数量由 video_mode 决定，不能增删
         ├ id / name          BG0 / BG1 / … / OBJ（可改用途名：远山/云…）
         ├ kind               tile / affine / bitmap / obj
         ├ tracks[]           轨道 id 列表 ← **顺序 = 从底到上的重叠顺序**
         ├ visible / scroll_x / scroll_y
     └ tracks[]              轨道（扁平列表，**老代码全用它**）
         └ kind               bg / char1..3 / text / voice / bgm / se / fx
     └ clips[]               片段（时间轴上的一块）
         └ track / start / dur / kind / ref / props
```

**两个刻意的设计**：

1. **`Scene.tracks` 保持扁平** —— 图层只额外记住"哪些轨道属于我"。
   这样时间轴、编译器、预览这些老代码**一行都不用改**。
   （加一级关系，不动原有结构 —— 这是"不做大改"的落点。）

2. **图层数 = 模式给的硬件层数**，界面上**没有"加图层"按钮**。
   能改的只有：用途名、可见性、滚动速度（视差用）。

### 3.2 图层表（`MODE_LAYERS`）

| 模式 | 图层 |
|---|---|
| 0 | BG0 BG1 BG2 BG3（tile）+ OBJ |
| 1 | BG0 BG1（tile）+ BG2（affine）+ OBJ |
| 2 | BG2 BG3（affine）+ OBJ |
| 3/4/5 | BG2（bitmap）+ OBJ |

⚠ **这份表和 `ui/video_modes.py` 里的说明是两份**（`core` 不能反向依赖 `ui`）。
两边不一致会被 `tests/test_layers.py::test_mode_layers_match_video_modes` 抓到。

### 3.3 界面结构（当前）

```
菜单栏：文件 编辑 「工作区」 视图 帮助               [导出 GBA]  ← 钉在菜单栏右端
┌──────────────┬──────────────────────────┬──────────────┐
│ 资源库(dock) │  预览（中央）             │ 属性(dock)   │
│ 素材/角色表   │  左上角浮着图层按钮        │              │
│              │  [BG0][BG1][BG2][OBJ][●]  │              │
├──────────────┴──────────────────────────┴──────────────┤
│ 时间轴 / 日志 / 工作区自己的面板（可停靠）               │
└─────────────────────────────────────────────────────────┘
```

- **没有顶部工具栏**（原来那一行已删）：文件操作在菜单栏，工作区切换在「工作区」菜单（Ctrl+1~4）
- **中央左侧是"可换的槽"**：工作区自己决定放什么（关卡工作区 → 地图小组件；剧情 → 空着）
- **图层选择器是浮在预览左上角的小控件**：横排按钮 `BG0/BG1/…/OBJ`（从左到右 = 从底到顶）

### 3.4 时间轴的行模型（`ui/timeline.py`）

```
rows() → [('layer', Layer), ('track', Track), ('track', Track), ('layer', Layer), …]
```
- **图层头一行**（`▼ BG0 图块层 17 段`）+ 它下面**缩进的轨道行**（左侧有归属竖线）
- 点箭头折叠/展开；点图层名 → 图层选择器跟着同步
- **折叠只影响"画不画"**，不影响 `visible_tracks()` 返回的集合（数据层不受影响）

### 3.5 预览渲染（`core/preview.py`）

- `state_at(scene, t)` 算出这一刻的画面状态
- **有图层时**：按图层从下往上叠（每层先铺自己的背景，再叠自己的立绘）
- **没有图层的旧场景**：走原来的单层路径 —— **老工程表现一个像素都不变**
- 预览是**真渲染器**（`tools/check-preview.py` 用它和实机逐像素比对），所见即所得

### 3.6 编译器与资源流水线（`core/compiler.py` + `tools/make_project_*.py`）

```
导出：scenario/scenario.txt  剧本（命令表）
      scenario/assets.json   资源清单（素材 → 索引）
      include/project_video.h 工程设置（显示模式、跳过标题）
      include/scenario.h      剧本索引
打包：build-assets.ps1
      1. build_script.py     剧本 → scenario.c（命令数组）+ 字符集
      2. make_cjk_font.py    字符集 → 字库（约 25 B/字）
      3. make_project_assets.py 图片 → GBA 格式（75 KB/张 240×160 16bpp）
      4. make_project_audio.py  音频 → 8bit 单声道 PCM（11 KB/秒 @11025 Hz）
      5. make_project_anim.py / make_project_level.py
      6. 产物自检（9 个关键文件）
编译：build.ps1 → arm-none-eabi-gcc → xxx.gba
```

**双预算（编辑器要能提示）**：
- **ROM**（32 MB 上限）：每一张烘好的图 75 KB
- **显存**（96 KB）：同时存在的图块/图块地图；位图模式一屏就吃掉 75 KB

### 3.7 素材自动转码（已经打通）

- **音频**：OGG / MP3 / FLAC / WAV → GBA 8bit PCM
  （`tools/audio_codec.py` 三级后端：soundfile → ffmpeg → 标准库 wave，带缓存）
- **图片**：任意尺寸/格式 PNG/JPG → 240×160 16bpp（BGR555）
- **开发者不需要懂 GBA 格式**，拖进工程就行

## 4. 移植流水线（从商业游戏解包数据到可玩 ROM）

> 这条流水线是**实战验证过的**：把一部 ADV 游戏的前 200 句（3 个场景）完整搬进了工程，
> 带真实背景调度、语音、说话人。也做过整套 8 盘卡带的完整移植。

```powershell
$A = "<解包目录>"      # 含 剧本\Rio\*.ws2、PNG输出、立绘、音频
$W = ".tmp\port"       # 工作目录

# 1) 从 .ws2 提取"真实调度"（哪一句配哪张图/哪条语音/谁说的）
python tools\ws2_scenes.py                    # → .tmp\ws2_scenes.json
# 2) 从 .ws2 提取"图层合成配方"
python tools\ws2_recipes.py                   # → .tmp\scene_recipes.json
# 3) 多层合成成一张 240×160
python tools\compose_scenes.py --recipes .tmp\scene_recipes.json --src "$A" `
       --out "$W\proj\assets\bg" --report "$W\comp_map.json"
# 4) TSV 台词 → 工程（前 N 句）
python tools\tsv_to_project.py --tsv "$A\剧本\台词对照_JP_CN.tsv" --out $W `
       --name "游戏名" --max-lines 200
# 5) 全量收素材进工程
python tools\collect_assets.py --src "$A" --project "$W\游戏名" --share 1/1
# 6) 带调度 + 预合成再转一次
python tools\tsv_to_project.py --tsv ".." --out $W --max-lines 200 `
       --scenes-json .tmp\ws2_scenes.json --composite-map "$W\comp_map_lines.json" --keep-assets
# 7) 从工程一条命令到 ROM
.\build.ps1 -Project "$W\游戏名\游戏名.gbastudio" -OutputName mygame -Clean
```

**几个必须知道的技术点**：

- **`.ws2` 是加密的 Rio 字节码**：解密 = **循环右移 2 位**（`rot_right2`）
- **操作码参数表**要从 `D:\GitHud\3DSStudio\tools\ws2ref\CLegacyFunctions.cs` 解析（249 条指令）
- **消息号和 TSV 索引对不上**（TSV 每场景从 0 开始，ws2 是全局编号）
  → 对齐只能靠**日文原文的指纹**（两边都算 MD5，`text_key()`）
- **素材文件名和内容不可信**：`bgBLACK.png` 的内容是纯红、`bgRED.png` 是纯白、`bgWHITE.png` 是纯黑
  —— 它们是**着色器色块**，要**按名字生成纯色**，不能读文件内容

## 7. 当前问题与已知限制（**接手前必读**）

### 7.1 结构性限制

1. **引擎还不支持多图层同时显示** ✗
   编辑器里有图层 ✓ 但引擎现在只认"一张背景" ✓
   → 所以**导出时把画面合成成一张** ✓ 画面是对的 ✓ 但**视差做不了** ✓
   → 导出时会明确提示这一点（`compiler.compile_project` 的 notes）
   → 要真正用上图层，得做**阶段 6**：给引擎加"多 BG 层 + 每层独立滚动"

2. **图层数由模式定死**，不能增删 —— 这是**硬件事实**，不是软件限制。
   想做视差就得在**创建项目时**选模式 0/1/2（图块模式），模式 3/4/5 只有一层。

3. **全烘位图的 ROM 代价**：每屏 75 KB。
   移植时 180 种图层组合 = 13.2 MB 还能接受，但"每句都换图"的玩法会爆。
   优化方向：按层判断"这层能不能用图块表示"（纯色块/重复图案 → 走图块，省几十倍）。
   **第一版刻意选择"先做对，再做省"。**

4. **关卡模式的"图层"与剧情模式的"图层"是两套**：关卡是图块地图（走格子玩法），
   剧情是时间轴图层。目前**并存**，没有合并。

### 7.2 未做的功能（用户提过、明确排期在后的）

### 7.3 环境性坑（换机器会再遇到）

| 坑 | 现象 | 处理 |
|---|---|---|
| `.ps1` 文件丢了 UTF-8 BOM | PowerShell 5.1 按 GBK 读 → 报莫名的语法错 | 保存时必须带 BOM（有测试守着） |

## 8. 踩过的坑（精华，最值钱的部分）

按"教训"归类，不是按时间。

### 8.1 素材的表象全都不可信

- **目录名不可信**：`立绘/` 目录里装的全是背景图
- **文件名不可信**：`bgBLACK.png` 的内容是纯红（三个色块文件全对调）
- **编号不可信**：TSV 的索引和 ws2 的消息号是两套编号
→ **规律：以引擎/原作里的语义为准，不要以素材表象为准。**

### 8.2 测试不能依赖"上次留下的东西"

一轮清理暴露了 **5 个"因为陈旧文件而假通过"的测试**：
- `test_level` 断言的路径早就改了，靠 `.tmp` 里的陈旧文件蒙过去
- `test_audio_data` 依赖 `test_export` 先跑，但顺序是反的，靠上次的 bin 蒙过去
- 测试夹具用了过期的（`.tmp` 删除**静默失败**导致）
- 生成器和仓库里的示例早就不同步（生成器造 1 张精灵帧，仓库那份有 5 张）
- `build_chapters.py` 语法都不成立，而测试全绿（**只把它当文本读，从没 import 过**）

> **"被测试提到过" ≠ "被测试验证过"。**
> **定期清一次工作区，是最好的测试体检。**

### 8.3 一次性脚本必须落成工具

图层合成配方原来是**会话里跑的内联脚本**生成的 → 清掉 `.tmp` 之后**没工具能重建它** → 整条流水线跑不动。
→ 补成 `tools/ws2_recipes.py`，并让 `build_chapters.py` 在缺表时自动生成。
> **把"临时的"当成"持久的"，代价会在很久以后才显现。**

### 8.4 解释器的顺序执行 + falsy 值

- `video_mode or 3` → **模式 0 是 falsy** → 被当成"没给" → 掉进默认值 3
  结果："模式 0 的工程建出来是模式 3 的图层表"（4 个图块层变成 1 个位图层）
  → **`or` 当默认值用，遇上合法的 0 就会静默出错**
- PowerShell 里把代码插到文件前半部分 → 撞两个"定义在后面"的坑
  （`Say` 函数还没定义、`$Python` 还是空的）
  → **PowerShell 是顺序执行的，用到的函数和变量必须先就位**

### 8.5 每帧路径上不能重建控件

图层选择器每帧被 `refresh_preview` 触发重建 → 按钮销毁了但**事件过滤器还挂着** → 悬空指针 → **进程段错误**（`0xC0000005`，连 Python 堆栈都没有）。
> **重建控件是重操作，不能放在每帧都会走的路径上。**
> 可怕之处：界面看起来完全正常，只有播一会儿才崩。

### 8.6 做不到的事要在导出时就说清楚

编辑器有图层、引擎不支持多层 → 如果导出后什么都不提，用户会以为视差能用，烧进 ROM 才发现不动。
→ 导出时明确提示"本版会合成成一张画面，层间还不能独立滚动"。

### 8.7 其它

- **`snd_init()` 只在标题路径里** → 跳过标题就整个音频没初始化（画面正常但一声不响，极难查）
- **`vn_begin()` 不清台词** → 重玩会闪上一局的最后一句
- **改了 `const char *` 指向的内容**：`s_speaker[0] = '\0'` 是往字符串字面量里写（未定义行为）
  → **动手前先看清类型**
- **C 数组名和指针**、**`Scene.tracks` 扁平 vs 图层归属** 这类"加一层关系不动原结构"的做法，
  在改动量大的时候特别值 —— 老代码一行不改，风险就低一个量级

## 9. 怎么继续（给接手的自己/别人）

**最小可用路径**（想快速看到东西）：
```powershell
python tests\run_all.py                       # 确认环境
双击 启动编辑器.pyw                            # 打开编辑器
# 新建项目 → 选显示模式 → 拖素材 → 排时间轴 → 导出 GBA → build.ps1
```

**想接着开发**，建议顺序：
1. **阶段 3**（自动转码可见化）—— 后端已通，一天能见效
2. **阶段 4**（属性面板 + 预览暂停 + 精灵缩放）—— 都是小改，体验提升明显
3. **阶段 6**（引擎多图层 + 独立滚动）—— **这一步才能让"图层"真正发挥作用**，
   评估结论是"中等改动，只动 `bg.c` + `vn.c`，加 2~3 条命令，不碰架构"
4. **阶段 7**（积木层）—— 最大的一块，建议单独排期

**每做一步都要**：
```powershell
python tests\run_all.py                        # 19 个测试不许红
.\build.ps1 -Project "<某个工程>" -Clean        # 引擎还能构建
```
