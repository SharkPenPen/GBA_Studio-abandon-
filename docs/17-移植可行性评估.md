## 一、先说结论

**能做出来，但只能是"精简版"：大约原作的 5%~10% 内容量。**

| 内容 | 原素材 | 32 MB 卡带能装 | 覆盖率 |
|---|---|---|---|
| **中文台词** | 5705 句（45 个 .lng） | **全量放得下** | **100%** ✅ |
| **背景** | 123 张 1280×720 + 大量 CG | ~150 张 | **大部分** ✅ |
| **立绘** | 150 张 1280×720 | ~60 张 | **40%** ⚠ |
| **BGM** | 10 首（13.4 MB OGG） | 6 首（需缩短） | 60% ⚠ |
| **音效** | 187 个（21.9 MB OGG） | 40 个（短的） | 21% ⚠ |
| **语音** | 1488 条 ≈ 90 分钟（82.5 MB） | **8 分钟** | **9%** ❌ |
| **视频** | 1 个 77.8 MB WMV | **0** | 0% ❌ |
| **特效** | 33 个 D3D 特效 | 只能做极简版 | ~0% ❌ |

**一句话**：能做出一个"**文字和画面基本完整、但几乎没有语音演出**"的 GBA 视觉小说。
文字是视觉小说的骨架，这一块**完全没问题**；缺的是**语音**这个灵魂。

## 三、会有什么问题（按严重程度排）

### 🔴 问题 1：语音装不下 —— 最大的硬伤

- 原语音 **82.5 MB OGG / 1488 条 / 约 90 分钟**
- GBA 要的是**未压缩 PCM**，转完体积再涨约 **10 倍** → 相当于 **800 MB**
- 卡带只有 32 MB → **只能放 1%**

**可选的做法**：
1. **只保留关键句**（每章开场、名场面）—— 例如 50 句 × 8 秒 ≈ 4.4 MB ✓
2. **全砍**，靠 BGM + 音效撑气氛 —— 视觉小说没语音也能玩，但表现力掉一档
3. 降低采样率（5734 Hz）能省一半，但语音会明显发闷

### 🔴 问题 2：剧本录入是最大的工作量

- 剧本 **511 个 .ws2**（已解密）、中文台词 **5705 句**（45 个 .lng）
- 编辑器的用法是**在时间轴上手工排** —— 5705 句手工排 ≈ **几十小时**，不现实
- **唯一的出路是写转换器**：`.ws2` + `.lng` → 编辑器的 `scenario.txt`
  你已经写了解包/解析器（报告里说 505/511 完整解析 ✓）→ **这一步是能不能做下去的关键**

### 🟠 问题 3：音频格式转换没有工具

- 素材是 **OGG**，而项目的音频管线**只吃 WAV**
- 这台机器上 **没有任何 OGG 解码器**（实测）：
  ```
  ffmpeg / ffprobe / oggenc / sox      都没有
  soundfile / librosa / audioread / pydub  都没装
  只有 Python 自带的 wave（读不了 OGG）
  ```
- **解法**：① 你自己的解包工具加一个"直接输出 WAV"的选项（最省事）
  ② 或者装一个 ffmpeg（解包工具目录里放一份就行）

### 🟠 问题 4：字库要从 254 字扩到 3500 字

- 现在字库只有 **254 个字**（够示例用），真实剧本需要 **3000~4000 个汉字**
- **容量完全不是问题**：3500 字 × 25 字节 ≈ **88 KB**（32 MB 里九牛一毛）
- 要改的是**工具和引擎的接口**：字库生成脚本 + 引擎的查表方式
- 这一步是**确定能做**的，只是要写

### 🟡 问题 5：素材要人工挑选

- `PNG输出` 里有 **3951 张** PNG，尺寸五花八门：
  ```
  1280×720   123 张   ← 背景 / CG（能当背景用）
  190×107    198 张   ← 多半是 UI / 缩略图
  54×20 / 48×14 / 44×10  各 180 张  ← 多半是图标/按钮
  40×40 / 70×70 / 30×30   ← 图标
  ```
- `背景` 目录里**只有 4 张**（logo/white/警告画面/black）—— **真正的场景背景在 `PNG输出` 里**
- `立绘` 目录 212 张里有 150 张是 1280×720 —— 但其中**不全是立绘**，很多是整张 CG（实测有几张"立绘"转换后人物包围盒就是整张图）
- **需要人工过一遍做分类**，这是纯体力活

### 🟡 问题 6：视频和特效只能放弃

- 视频 77.8 MB WMV → GBA 没有视频解码，逐帧位图化体积会爆炸 → **放弃**
- 33 个 D3D 特效 → GBA 没有 3D 硬件 → 只能用 mode 1/2 的**仿射层**做极简版（旋转/缩放）

### ✅ 不是问题的部分

- **中文文本** ✓ 5705 句 ≈ 230 KB，随便放
- **背景颜色** ✓ 模式 3 是 16 位直接色（32768 色），照片级背景原样显示
- **立绘透明** ✓ 转换器能处理 alpha（不透明时自动改用抠白底，实测有效）
- **双语对照** ✓ 你的 .lng 已经导出了 5705 条中文，比从 .ws2 里抠省事

## 四、建议的第一步（**别先挑素材**）

现在的瓶颈**不是素材**，是**两条链路没通**。先做这两件：

### 第 1 件：把音频链路打通

1. 用你的解包工具（或装 ffmpeg）把 **1 条语音 + 1 首 BGM** 转成 WAV
2. 放进工程 → 导出 → 编译
3. 在 mGBA 里**听到声音**为止
4. 量出"1 秒语音占多少 ROM" → 才能决定语音留多少

### 第 2 件：写剧本转换器（**这是关键**）

1. 从 511 个 `.ws2` 里挑**一章**
2. 写 `.ws2` + `.lng` → `scenario.txt` 的转换器
3. 转一章，在编辑器里打开看**还原度**：台词、说话人、背景切换、立绘显隐
4. 修订规则 → 再批量转

### 第 3 件（可选）：字库扩容

把 254 字扩到 3500 字 —— 容量没问题，主要是把生成脚本和引擎的查表接口改对。

**这三件做完，才会知道"到底能转多少章"**。现在挑素材是白费力气 ——
因为一条语音都放不进去的时候，挑再多图也没用。

## 五、顺手修掉的一个真问题

做切片时**引擎直接编译不过**：

```
error: 'gfx_logo_asset' undeclared
```

- 引擎的标题画面要引用 LOGO，而资源生成器**只在工程里有 logo 时才声明它**
- 新建的工程没有 logo → **整份代码编不过**
- 背景和立绘都有"空表兜底"，**唯独 logo 漏了** —— 典型的泛化漏洞
- 已修：头文件里无条件声明 + C 文件里给一个 0×0 的空资源
- **这个 bug 只有"真的建一个新工程走一遍"才会暴露** —— 光看示例工程永远遇不到

## 六、总结成几句话

1. **文字和画面**基本都能搬 —— 这是视觉小说的主体，**没问题** ✓
2. **语音只能保留不到一成** —— 这是最硬的限制，得先想好怎么取舍 ❌
3. **真正的工作量在"剧本转换器"**，不在素材挑选 —— 5705 句手工排不现实
4. **先打通音频和剧本两条链路**，再谈批量 —— 否则挑素材是白做工
5. 视频和特效放弃，字库扩容是确定能做的活
