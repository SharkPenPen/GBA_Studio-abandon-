## 一、硬件规格

| 项目 | 规格 | 意味着什么 |
|---|---|---|
| CPU | ARM7TDMI @ **16.78 MHz** | 比同期 PC 慢上百倍，优化很重要 |
| 指令集 | ARM（32 位）+ Thumb（16 位） | 默认用 Thumb，省空间 |
| 每帧时间 | **280,896 周期**（59.73 fps） | 你每帧的全部预算，超了就掉帧 |
| 屏幕 | 240×160，**15 位色**（BGR555） | 红/绿/蓝各 5 位，0~31 |
| 内部内存 IWRAM | 32 KB @ `0x03000000`（32 位总线，**快**） | 变量、栈 |
| 扩展内存 EWRAM | 256 KB @ `0x02000000`（16 位总线，慢） | 大块数据 |
| 显存 VRAM | 96 KB @ `0x06000000` | tile / 位图 / 地图 |
| 调色板 | 1 KB @ `0x05000000` | 512 个 15 位颜色 |
| 精灵属性 OAM | 1 KB @ `0x07000000` | 128 个精灵 |
| 卡带 ROM | 最大 32 MB @ `0x08000000` | 你的游戏本体 |
| 存档 | SRAM 32 KB / Flash 64~128 KB / EEPROM 512 B~8 KB @ `0x0E000000` / `0x0D000000` | 三种，靠探测区分 |
| 声音 | 4 个声道（2 方波 + 1 波形 + 1 噪声）+ 2 个 DMA PCM | 音质相当于加强版 GB |

**最重要的一条直觉**：RAM 一共只有 288 KB。写代码时要时刻想着"这东西占多少 RAM"。

## 二、内存地图

```
0x00000000  BIOS（16 KB，只读，里面有 SWI 系统调用）
0x02000000  EWRAM  256 KB   ← 慢，放大数据
0x03000000  IWRAM   32 KB   ← 快，放变量和栈
0x04000000  I/O 寄存器      ← 硬件开关都在这里
0x05000000  调色板   1 KB
0x06000000  VRAM    96 KB   ← 画面数据
0x07000000  OAM      1 KB   ← 精灵
0x08000000  卡带 ROM 最大 32 MB
0x0E000000  卡带存档（SRAM / Flash）
```

`libtonc` 已经把这些地址定义好了，不用自己记数字：

| 地址 | libtonc 里的名字 |
|---|---|
| `0x04000000` | `REG_DISPCNT` |
| `0x04000130` | `REG_KEYINPUT` |
| `0x05000000` | `pal_bg_mem` / `pal_obj_mem` |
| `0x06000000` | `vid_mem`、`tile_mem`、`se_mem` |
| `0x07000000` | `oam_mem` |

## 三、显示模式（`REG_DISPCNT` 的低 3 位）

| 模式 | 类型 | 说明 | 显存占用 |
|---|---|---|---|
| 0 | 4 个 tile 背景层 | **商业游戏最常用**，硬件拼 8×8 图块 | 按 tile 算 |
| 1 | 2 个 tile 层 + 1 个旋转缩放层 | 常见组合 | 按 tile 算 |
| 2 | 2 个旋转缩放层 | 赛车/飞行类 | 按 tile 算 |
| 3 | 1 个位图层，240×160，**16 位色** | 最直观，本工程第一个程序用的就是它 | 76,800 B |
| 4 | 2 个位图层，240×160，8 位色（调色板） | 支持双缓冲翻页 | 2 × 38,400 B |
| 5 | 1 个位图层，160×128，16 位色，双缓冲 | 小画面 + 翻页 | 2 × 40,960 B |

**入门的正确顺序**：先用模式 3 理解"像素 = 显存里的一个数"（本项目已经做了），
然后尽快转到**模式 0 + tile**——那才是 GBA 真正的工作方式。Tonc 的
"Tile/map" 和 "Regular background" 章节讲这个。

模式 3 的取像素公式：

```c
vid_mem[y * 240 + x] = RGB15(r, g, b);
```

## 四、常用寄存器

`REG_` 开头的宏来自 `tonc_memmap.h`，赋值就是配硬件。

| 寄存器 | 地址 | 作用 |
|---|---|---|
| `REG_DISPCNT` | `0x04000000` | **显示总开关**：模式、开哪几层、开精灵、开窗口 |
| `REG_DISPSTAT` | `0x04000004` | 显示状态与中断（VBlank/HBlank/VCount 中断） |
| `REG_VCOUNT` | `0x04000006` | 当前扫描到第几行（0~227） |
| `REG_BG0CNT`~`BG3CNT` | `0x04000008`+ | 各背景层的：图块库位置、地图位置、优先级、尺寸 |
| `REG_BG0HOFS`/`VOFS` | `0x04000010`+ | 背景层滚动（做卷轴地图用） |
| `REG_WIN0H`/`WIN0V`/`WININ`/`WINOUT` | `0x04000040`~ | 窗口（局部特效区域） |
| `REG_MOSAIC` | `0x0400004C` | 马赛克效果 |
| `REG_BLDCNT`/`BLDALPHA`/`BLDY` | `0x04000050`~ | 混合、淡入淡出、亮度调节 |
| `REG_KEYINPUT` | `0x04000130` | 按键状态（注意：**0 表示按下**，libtonc 帮你取反了） |
| `REG_KEYCNT` | `0x04000132` | 按键中断 |
| `REG_IE`/`REG_IF`/`REG_IME` | `0x04000200`~ | 中断使能 / 中断标志 / 中断总开关 |
| `REG_WAITCNT` | `0x04000204` | 各区域等待周期（影响 ROM/RAM 访问速度） |
| `REG_DMA0SAD`~ DMA3 | `0x040000B0`~ | DMA 传输（搬运数据不占 CPU） |
| `REG_TM0D`~ TM3 | `0x04000100`~ | 4 个定时器 |
| `REG_SOUNDCNT_X` | `0x04000084` | 声音总开关 |

### `REG_DISPCNT` 常用位（libtonc 的宏）

```c
REG_DISPCNT = DCNT_MODE0      // 显示模式
            | DCNT_BG0        // 打开 0 号背景层
            | DCNT_BG1
            | DCNT_OBJ        // 打开精灵层
            | DCNT_OBJ_1D;    // 精灵用一维排布（推荐）
```

## 五、按键

| 按键 | libtonc 宏 | 硬件位 |
|---|---|---|
| A | `KEY_A` | 0x0001 |
| B | `KEY_B` | 0x0002 |
| SELECT | `KEY_SELECT` | 0x0004 |
| START | `KEY_START` | 0x0008 |
| → | `KEY_RIGHT` | 0x0010 |
| ← | `KEY_LEFT` | 0x0020 |
| ↑ | `KEY_UP` | 0x0040 |
| ↓ | `KEY_DOWN` | 0x0080 |
| R | `KEY_R` | 0x0100 |
| L | `KEY_L` | 0x0200 |
| 任意方向键 | `KEY_DIR` | 0x00F0 |
| 任意键 | `KEY_ANY`/`KEY_MASK` | 0x03FF |

**必须先 `key_poll()`，再用 `key_*` 系列函数**，否则读到的是上一次的快照：

```c
vid_vsync();
key_poll();
if (key_hit(KEY_A))       { /* 刚按下，只触发一次 */ }
if (key_is_down(KEY_B))   { /* 按住期间一直为真 */ }
int dx = key_tri_horz();  // ← -1, 没按 0, → +1（长按自动重复）
int dy = key_tri_vert();  // ↑ -1, ↓ +1
```

## 六、颜色与调色板

GBA 用 15 位色：`0b0BBBBBGGGGGRRRRR`（最高位不用）。

```c
u16 red   = RGB15(31,  0,  0);
u16 white = RGB15(31, 31, 31);
u16 gray  = RGB15(16, 16, 16);
```

- 调色板共 512 项：`pal_bg_mem[0..255]` 给背景，`pal_obj_mem[0..255]` 给精灵。
- **背景调色板的第 0 项是透明色**，精灵调色板的第 0 项也是透明——画图时会用到这个特性。
- 颜色只有 5 位精度，所以渐变会有明显台阶。想要平滑渐变要用
  "混合（blend）+ 抖动（dither）"技巧，Tonc 有专章。

## 七、性能预算怎么算

每帧 280,896 个周期。举例估算：

| 操作 | 大约耗时 |
|---|---|
| 用 32 位写入清空模式 3 全屏 | 19,200 次写入。**实测约吃掉一帧的 60%** —— 别每帧调用 |
| 画一个 16×16 方块 | 256 次写入，可忽略 |
| 画一行 30 个字符的文字 | 约 2,000~3,000 周期，可忽略 |
| 一次整数除法（变量） | ARM7TDMI **没有除法指令**，软件实现约 20~50 周期，能免则免 |
| 一次浮点乘法 | 软件模拟，约上百周期，**GBA 上基本不要用 float** |

> **实测教训（本工程真实踩过）**：一帧里"清屏 + 画边框 + 画文字"看起来没多少活，
> 但光清屏就占掉 60%，结果整帧的绘制时间超过了电子束扫描速度，
> 表现为**屏幕上半部分永远显示不出来**（电子束已经扫过去了）。
> 正确做法是**局部重绘**：静态背景只画一次，动态元素只在变化时擦除重画。
> 完整分析见 [docs/02-第一个ROM.md](02-第一个ROM.md) 第五节。

**实践建议**：

- 能不除就不除，乘法代替除法，或用查表（libtonc 提供 `div_lut`、`sin_lut`）；
- 避免浮点，用定点数（例如"像素 × 256"存成整数）；
- 大块搬运交给 DMA（`REG_DMA3SAD` 之类），不占 CPU；
- 只在 VBlank 期间改 VRAM/调色板/OAM，否则可能闪烁。

## 八、常见坑

| 现象 | 原因 |
|---|---|
| 画面横向撕裂 | 在屏幕刷新中途改显存。用 `vid_vsync()` 对齐帧 |
| 实机白屏，模拟器正常 | ROM 头不对（Logo / 校验和）。跑 `scripts\check-rom.ps1` |
| 程序跑飞、行为诡异 | 栈溢出。IWRAM 只有 32 KB，栈和全局变量共享 |
| 大数组导致编译后 RAM 不够 | 全局变量默认放 IWRAM，大数组要显式放到 EWRAM |
| 画面抖动/闪烁 | 边画边显示。双缓冲（模式 4/5）或只在 VBlank 改数据 |
| 按一次触发多次 | 用了 `key_is_down` 而不是 `key_hit` |
| 除法/浮点让帧率崩了 | ARM7TDMI 无除法、无 FPU，改用定点或查表 |
