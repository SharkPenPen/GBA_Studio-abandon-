# 01 · 环境说明：装了什么、装在哪、为什么这么装

## 一、你这台机器的网络现状（实测结论）

搭建 GBA 工具链时，第一步就撞到了网络问题。以下是本机实测结果，不是猜测：

| 目标 | 结果 | 说明 |
|---|---|---|
| `github.com` | ❌ 超时 | 被阻断 |
| `raw.githubusercontent.com` | ❌ 超时 | 被阻断 |
| `objects.githubusercontent.com` | ❌ 超时 | **GitHub Release 附件真正存放的域名** |
| `codeload.github.com` | ❌ 超时 | 仓库打包下载域名 |
| `devkitpro.org` | ❌ 403 | Cloudflare 返回 "Sorry, you have been blocked" |
| `pkg.devkitpro.org` | ❌ 403 | 同上，软件包仓库被拦 |
| `api.github.com` | ✅ 200 | **可达**，只有 API 通 |
| 清华 / 中科大 / 阿里云镜像 | ✅ 200 | 可达 |
| GitHub 加速代理（ghfast.top 等） | ✅ 200 | 可达 |

两个关键推论：

1. **官方 devkitPro 路线走不通。** 它的安装器从 GitHub Release 下载（域名被阻断），
   装完之后又要从 `pkg.devkitpro.org` 拉软件包（被 Cloudflare 拦）。
   两处都过不去，所以不是"下载慢"，是根本拿不到。
2. **但 GitHub 的内容可以通过加速代理取到。** 实测下载 devkitPro 安装器时，
   拿到的文件不仅字节数完全一致，**Windows 数字签名校验还是 `Valid`**，
   签名者是 `E=davem@devkitpro.org, CN="Open Source Developer, David Murphy"`
   —— 也就是说代理没有篡改内容。

## 二、因此采用的方案

既然拿不到 devkitPro，就自己组装一套等价的工具链。
这条路不是野路子：[gbadev.net](https://gbadev.net/getting-started.html) 在
"Development from scratch" 一节里明确推荐了 **gba-bootstrap**——用普通
`arm-none-eabi-gcc` 构建 GBA ROM 的官方示例。我们正是采用它。

| 需要的东西 | 官方 devkitPro 方案 | 本工程方案 | 完整性校验 |
|---|---|---|---|
| ARM 交叉编译器 | devkitARM | xPack GNU Arm Embedded GCC 15.2.1 | **官方 SHA256** |
| 硬件抽象库 | libtonc 预编译包 | libtonc 源码，本地编译 | **逐文件 Git blob SHA1** |
| 启动代码 crt0 | devkitARM 内置 | gba-bootstrap `gba_crt0.s` | **逐文件 Git blob SHA1** |
| 链接脚本 | devkitARM 内置 | gba-bootstrap `gba_cart.ld` | **逐文件 Git blob SHA1** |
| newlib 桩函数 | libgba | gba-bootstrap `syscalls.c` | **逐文件 Git blob SHA1** |
| ROM 头修复工具 | gbafix | `tools\gbafix.ps1`（用 PowerShell 重写） | 对照 gbafix 源码实现 |
| 构建系统 | make + Makefile | `build.ps1` | —— |
| 模拟器 | mGBA 0.10.5 | mGBA 0.10.5（免安装） | 字节数（该 release 官方未发布摘要） |
| 备用模拟器 | —— | NanoBoyAdvance 1.8.3、SkyEmu v5（**已删除**，见下） | 两者均有**官方 SHA256** |

> **模拟器最终选型过程**（值得记一笔）：
> mGBA 的 Windows 版只有 `.7z` 便携包和需要提权的安装器，一开始解不开：
> Windows 自带 tar 的 libarchive 不支持 7z 的 LZMA 编码，Python 的 py7zr
> 又恰好不支持这个包用的 BCJ2 滤波器。
> 最后发现 **7-zip.org 在国内可以直连**，于是下载官方独立解压器 `7zr.exe`（600KB）
> 完成解压——这一步现在写在 `scripts\setup-emulator.ps1` 里，可重复执行。
>
> 另外两个模拟器（NanoBoyAdvance / SkyEmu）包得更"干净"（zip / 单文件 exe），
> 但在**本机加载 ROM 时会崩溃**（`0xc0000005`）。已排除 ROM 问题、运行库缺失、
> 杀软注入、显卡不足（本机是 RTX 4070 Ti SUPER），因此不作为默认，
> 并在后续整理磁盘时删掉了（想再试可以重新下载，两者都是 zip/单文件，无需安装）。
> mGBA 实测正常：标题栏显示 `GBA AI DEMO (60 fps)`，截图画面与代码逐项吻合。

### 校验是怎么做的（为什么可以信）

- **编译器**：GitHub API 直接给出了官方公布的 SHA256
  （`bae6a3d1...93ea`），下载后逐字节比对。API 是**直连**的，不经过代理，
  所以校验基准本身可信。
- **源码**：先用直连的 `api.github.com` 取回仓库的完整文件清单，
  清单里每个文件都带 git blob SHA1；再逐文件经代理下载，
  本地按 `sha1("blob <长度>\0" + 内容)` 重算并比对。
  这样即使代理想动手脚，也会在 SHA1 上暴露。
- **不依赖 codeload**：代理拒绝转发 codeload 的打包下载（返回 403），
  所以改用"逐文件"方式，反而换来了更细粒度的校验。

## 三、装在哪

所有东西都在工程目录内，**没有写注册表，没有装到系统目录，没有要管理员权限**：

```
D:\GitHud\GBA_AI\
├─ .toolchain\
│   ├─ arm-none-eabi-gcc\        ARM 编译器（bin\arm-none-eabi-gcc.exe 等）
│   ├─ libtonc\                  libtonc 源码 + 头文件
│   ├─ lib\libtonc.a             ← 本地编译出的静态库
│   ├─ build\libtonc\            编 libtonc 时的中间文件
│   └─ gba-bootstrap\            启动代码、链接脚本、许可证
├─ .toolchain\mgba\              mGBA 0.10.5 免安装版（能正常试玩的那个）
└─ .tools\                       下载缓存（7zr.exe 等）
```

这样做的好处：

- 整个工具链是**可移植**的，拷到别的电脑也能用（路径写在脚本里，不依赖环境变量）；
- 想推倒重来，删掉 `.toolchain\` 再跑一次安装脚本即可；
- 不污染系统，不需要管理员权限。

**没有往系统里装任何东西**——连模拟器都是免安装的：

| 位置 | 内容 | 怎么来的 |
|---|---|---|
| `.toolchain\mgba\` | **mGBA 0.10.5（默认模拟器，已实测可用，50 MB）** | 7z 经加速代理下载 + `7zr.exe` 解压 |
| `.toolchain\arm-none-eabi-gcc\` | ARM 交叉编译器（1425 MB，工程里最大的东西） | 官方 zip，SHA256 校验通过 |
| `.toolchain\libtonc\` + `lib\libtonc.a` | libtonc 源码与编译产物 | 逐文件 SHA1 校验 |
| `.toolchain\gba-bootstrap\` | 启动代码、链接脚本、许可证 | 逐文件 SHA1 校验 |
| `.tools\7zr.exe` | 7-Zip 官方独立解压器，用于解 mGBA 的 7z | 7-zip.org 直连下载 |
| `.tools\pylibs\` | ⚠️ 失败尝试的残留（py7zr 解不开 BCJ2 滤波器，改用 7zr.exe 后无用） | 从清华 PyPI 镜像装入工程目录，**没动系统 Python** |

> 整理磁盘时已删除：编译器与模拟器的压缩包（349 MB，内容早已解压）、
> devkitPro 安装器（官方源被拦，用不上）、NanoBoyAdvance 与 SkyEmu（62 MB，本机会崩）。
> 工程从 1.9 GB 降到约 1.48 GB，剩下的 1.43 GB 是编译器本体，省不掉。

> `.tools\pylibs\` 删不掉：它身上有一条继承自 `.tools\` 的
> 「Everyone：拒绝 删除子文件夹及文件」权限条目（DSH 沙箱写入的），Deny 优先于 Allow。
> 手动删除步骤见 [README 常见问题](../README.md)。它不影响任何功能。

**精简占用**：`.\scripts\clean-caches.ps1` 可以随时清理下载缓存与编译中间产物
（`-Preview` 只预览，`-IncludeUnusedEmulators` 连上面那两个用不了的模拟器一起删）。

**唯一的不足**：mGBA 那个 release 官方没发布校验值（GitHub API 的 `digest` 字段为 null），
所以只校验了字节数（14,156,919）与解压是否成功，没有密码学级别的完整性证明。
其余所有组件都有官方 SHA256 或 Git blob SHA1 校验。

## 四、怎么确认装好了

```powershell
# 编译器在不在
.\.toolchain\arm-none-eabi-gcc\bin\arm-none-eabi-gcc.exe --version

# libtonc 编出来没有（执行 install 后第一次 build 会自动编）
.\scripts\build-libtonc.ps1

# 端到端验证：编一个 ROM 出来
.\build.ps1
```

`.\build.ps1` 输出里出现这些就算通了：

```
[build] 编译通过（N 个源文件）
[gbafix] 已修复 ROM 头：gba_ai.gba
[check] 结论：ROM 头合法，可以加载到模拟器/烧录卡。
[build] 构建成功。
```

## 五、和官方方案的差异（看教程时要注意的地方）

大部分 Tonc 教程假设你用 devkitARM + make，所以：

| 教程里写的 | 在本工程里 |
|---|---|
| `make` | `.\build.ps1` |
| `make clean` | `.\build.ps1 -Clean` |
| `#include <tonc.h>` | 一样，不用改 |
| libtonc 的函数调用 | 一样，不用改 |
| `$(DEVKITARM)/gba_rules` | 不适用（我们用 `build.ps1` 里的编译参数） |
| 用 `grit` 转换图片 | 暂未接入，见 `docs\04-学习路线.md` 的说明 |
| `-ltonc -lmm`（maxmod 音频） | 只有 `-ltonc`，音频暂未接入 |

**代码层面几乎完全兼容**：你从 Tonc 教程抄来的 `REG_DISPCNT`、`vid_mem`、
`key_poll()` 这些用法都是通用的，因为它们来自 libtonc 而不是编译系统。

## 六、如果以后有了可用代理/VPN

有两条升级路线：

1. **继续用现在这套**（推荐）。它已经能编出合法 ROM，没有理由换。
2. **切到官方 devkitPro**：关掉代理后运行
   `docs\optional-devkitpro\install-devkitpro.ps1`
   （保留着，但当前网络下必然失败），然后就可以用同目录那份官方 `Makefile`。
   需要把 `Makefile` 从 `docs\optional-devkitpro\` 复制回根目录。

如果哪天想用 `grit`（官方图片转换工具，集成在 devkitPro 的 `gba-dev` 包里），
走路线 2 最省事。
