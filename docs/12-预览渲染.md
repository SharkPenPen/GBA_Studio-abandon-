# 12 · 预览渲染（P3）

编辑器中央的监视器现在**不是示意图，是真实渲染**——和实机逐像素一致。

---

## 一、为什么能保证一致

三条线都走**同一套代码/常量**，不做"另一套近似实现"：

| 环节 | 实机（ROM） | 编辑器预览 |
|---|---|---|
| 布局常量 | `source/galgame.c` 的 `BOX_X/BOX_Y/…` | `core/preview.py` 里同名常量 |
| 排版换行 | `source/text.c` 的 `text_layout` | `layout_text()` 照着重写 |
| 字形点阵 | `tools/make_cjk_font.py` | **import 同一个模块** |
| 立绘转换 | `tools/make_assets.py` | **import 同一个模块** |
| 色深 | 硬件 5 位色 | `quantize_bgr555()` 同样量化 |

**验收工具**：`python tools/check-preview.py`

它拿 mGBA 的真实截图和预览渲染逐像素比：

```
截图         差异像素    占比       判定
s7.png      1          0.003%     ✅ 一致
s9.png      50         0.130%     ✅ 一致
s6.png      39         0.102%     ✅ 一致
结论：✅ 预览与实机逐像素一致
```

（剩下这几个像素是 ▼ 光标闪烁的相位差，不是渲染错误。）

## 二、踩过的坑（都是"看起来渲染错了，其实是别的问题"）

### 1. 裁剪偏 1 像素 → 差异率 57%

一开始我用公式估算 mGBA 窗口里游戏区的位置，结果偏了 1 像素。
**1 像素的偏移让差异率从 0.003% 变成 57%** —— 界面看起来"完全不对"，
但其实是量错了地方。

后来改成**穷举搜索"正好 240×160 的整数裁剪"**（绝不缩放，一缩放就重采样）：

```
最佳裁剪 (8,57)   差异 1 像素
次佳裁剪 (7,57)   差异 5103 像素
```

差 1 个像素差 5000 倍 —— 所以对比测试**必须先对齐**，否则结论毫无意义。

### 2. 立绘不见了 → 找错目录

`make_assets.make_character()` 是按 `GFX_DIR + 文件名`找源图的（那是编译时的约定），
而项目里素材在 `assets/char/<角色>/` 子目录。它去 `graphics/normal.png` 找，
找不到就静默返回空图 —— 表现为"预览里立绘凭空消失"。

修法：调用前把 `GFX_DIR` 临时指到该文件所在目录。
**这类"静默失败"最坑，所以现在缺素材会直接在信息栏报出来**：

```
第 1 句 · 海岸.png · 1 个立绘 ⚠ 角色表里没有 id=不存在的角色
```

### 3. 颜色差一点 → 忘了 5 位色

GBA 每通道只有 32 级色。8 位原图直接显示会比实机"更顺滑"，
实机上会出现色带。现在渲染最后统一量化到 5 位色 ——
**编辑器里看到的颜色就是实机能显示的颜色**。

## 三、用法

| 操作 | 效果 |
|---|---|
| 拖时间轴上的播放头 / 点顶部刻度 | 预览跟着变（"第 N 句 · 背景 · M 个立绘"） |
| **空格** 或「▶ 播放」 | 按时间轴走一遍，到末尾自动停 |
| Ctrl+滚轮 | 缩放时间轴（预览的 2×/3×/4× 在下拉框里） |
| 改台词/换立绘/拖片段 | 预览立刻刷新 |

性能：首帧约 200 毫秒（字体 + 素材转换，之后缓存），
**之后每帧 0.2 毫秒** —— 播放 30fps 毫无压力。

---

## 四、改引擎时要注意

`core/preview.py` 顶部那份常量表**必须和 `source/galgame.c` 同步**。
改了引擎的框位置/行距/精灵位置而忘了改预览，两边就会不一致。

**改完跑一次 `python tools/check-preview.py` 就能发现。**

同理，改 `make_cjk_font.py`（字号/字形）或 `make_assets.py`（缩放方式）之后也要跑。
