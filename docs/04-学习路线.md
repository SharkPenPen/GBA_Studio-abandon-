# 04 · 学习路线与下一步

你已经有一个能跑通"写代码 → 编译 → 模拟器里玩"的完整环境。
接下来是怎么把它变成一个真正的游戏。

---

## 一、推荐的学习顺序

**主线读物是 [Tonc](https://gbadev.net/tonc/)**（作者就是 libtonc 的作者，
gbadev.net 官方推荐"目前最好的 GBA 教程"）。按下面这个顺序读，
每读一章就回到本工程改代码验证。

| 顺序 | Tonc 章节 | 你会学到 | 在本工程怎么验证 |
|---|---|---|---|
| 1 | *Foreword* + *Setup* | GBA 是什么、工具链概念 | 你已经跳过了（环境已搭好） |
| 2 | **Hello World** | 最小可运行程序、`REG_DISPCNT` | 改 `source\main.c` 的底色 |
| 3 | **Bitmap modes** | 模式 3/4/5、显存公式 | 现在这个程序就是模式 3 |
| 4 | **Keys** | 按键的三种读法、长按重复、组合键 | 练习 3（按住 B 缩小） |
| 5 | **Registers / Memory map** | I/O 寄存器、内存分区 | 读 `docs\03-GBA硬件速查.md` 对照 |
| 6 | **Video basics** | tile、调色板、地图、图层 | ★ 从这里开始脱离"直接画点" |
| 7 | **Regular background** | 模式 0 背景层、滚动、地图 | 做一个能滚动的关卡 |
| 8 | **Sprites / Objects** | OAM、精灵、动画帧 | 把方块换成会动的角色 |
| 9 | **Affine background / sprites** | 旋转缩放 | 做背景旋转或角色转向 |
| 10 | **Text / TTE** | 屏幕文字、调试输出 | 显示分数、血量 |
| 11 | **Interrupts / Timers / DMA** | 中断、定时器、DMA 搬运 | 用定时器做音乐节拍 |
| 12 | **Sound** | 4 声道音频 | 加音效（难点，见下） |
| 13 | **Mode 7 / 3D**（进阶） | 伪 3D | 赛车类玩法 |

**不要按顺序硬啃全部**。建议：2→3→4→6→7→8→10 走完，
你就能做出一个有背景、有角色、有文字的完整小游戏了。

## 二、里程碑清单

把目标拆成能"看得见结果"的小步，每完成一个都能玩：

### M1 · 让方块听你的话 ✅ 已完成
本工程现在的状态。移动、换色、回中心。

### M2 · 屏幕上有字 ✅ 已完成
用 libtonc 的 **TTE（Tonc Text Engine）** 在屏幕上打印文字。
这是调试的刚需——没有 `printf`，看不了变量，一切靠屏幕。

**已经做好了**：`source\console.c` + `include\console.h` 就是这一层封装。两种用法：

```c
con_printf(4, 14, "POS %d,%d", player.x, player.y);   // 指定位置画一行（推荐）
iprintf("HP: %d\n", hp);                              // 像 PC 上一样用，自动换行
```

它做的事：
- `con_init()` 里用 `tte_init_bmp(3, &sys8Font, NULL)` 接上模式 3 的位图文字渲染器
  （字体数据 `src\font\sys8.s` 是 libtonc 自带的，不需要图片转换工具）；
- 覆盖了 newlib 的 `_write()`（在 `source\sys\syscalls.c` 里标记为 `__attribute__((weak))`，
  所以能被替换），把 `printf`/`iprintf` 的输出转交给 TTE；
- 调用 `setvbuf(stdout, NULL, _IONBF, 0)` 关掉 stdout 缓冲，
  否则 printf 的输出会攒着不显示。

**两个必须知道的限制**：

1. `tonc_tte.h` 里写着 `#define tte_printf iprintf` —— `tte_printf` 只是整数版 printf，
   本身不认识屏幕；真正让它显示的是我们覆盖的 `_write()`。
2. `tte_init_con()` 在本工程里**不可用**：那是 devkitPro 定制版 newlib 的专有功能
   （见 `scripts\build-libtonc.ps1` 里的排除说明）。
3. `sys8` 是 8×8 点阵字体，**只有 ASCII**，没有中文。要显示中文得自己做点阵字库
   （把汉字转成 1bpp/4bpp 位图数据，再用 TTE 的自定义字体接口）。

**另外，做这一步时踩了两个坑，都写在 [docs/02-第一个ROM.md](02-第一个ROM.md) 第五节里**：
绘制顺序要跟电子束扫描顺序一致；一帧画不完整屏时必须改成"局部重绘"。
这两条是 GBA 图形编程的地基，务必先看懂。

### M3 · 用图片画背景（tile 模式）
从模式 3 换到模式 0：图片转成 tile + 调色板 + 地图，硬件拼接。
这是 GBA 真正的工作方式，也是效率的分水岭。

**⚠️ 本工程目前缺一步**：官方工具 `grit`（PNG → tile）集成在 devkitPro 包里，
当前网络拿不到。三个选择：

1. **让我写一个 Python 版转换器**（推荐）。本机已装 Python + Pillow，
   我可以写一个 `tools\png2tiles.py`，功能覆盖常见需求：
   4bpp/8bpp、16 色调色板、map、精灵、透明色。跟 grit 不完全一样，
   但足够做游戏，而且参数更好懂。
2. 手写 tile 数据（8×8 的 4bpp 图块只有 32 字节，适合做小实验）。
3. 以后有可用的代理/VPN 时切到官方 devkitPro（见 `docs\01-环境说明.md` 第六节），
   直接用 grit。

### M4 · 有精灵（会动的角色）
OAM、精灵调色板、一维/二维排布、动画帧切换。
Tonc 的 "Sprites" 章节 + `tonc_oam.h`。

### M5 · 有游戏玩法
碰撞检测、状态机（标题画面/游戏中/暂停/结算）、分数、关卡数据。
到这里就不需要新知识了，是纯写代码。

### M6 · 有声音
GBA 有 4 个声道 + 2 个 DMA PCM 通道。两条路：

- **直接写寄存器**（Tonc 的 Sound 章节）：能出声，但要自己写混音。
- **maxmod 音频库**：`-lmm`，devkitPro 包的一部分，当前网络拿不到。

建议先用寄存器和 libtonc 内置的 `tonc_sound` 做简单音效，
背景音乐等到 M7 之后再考虑。

### M7 · 上实机
用烧录卡在真 GBA / GBA SP / NDS 上跑。这是最有成就感的时刻，
也是暴露"模拟器宽容、实机严格"的地方（ROM 头、时序、省电模式）。

### M8 · 发布
- [itch.io](https://itch.io/)（GBA 自制游戏社区很活跃）
- [GBA Homebrew Games 数据库](https://hh.gbdev.io/games/gba)
- [GBA Jam](https://gbadev.net/)（每年举办，评审 + 交流）

## 三、调试手段（很重要，但很多人不知道）

**本机已装好的模拟器**（在 `.toolchain\mgba\` 里，免安装）：

| 模拟器 | 位置 | 实测状态 |
|---|---|---|
| **mGBA 0.10.5**（默认） | `.toolchain\mgba\mGBA-0.10.5-win64\mGBA.exe` | ✅ **正常**：标题栏显示 `GBA AI DEMO (60 fps)`，截图画面与代码逐项吻合 |
| mGBA SDL 版（备用） | 同目录 `mgba-sdl.exe` | 界面版出问题时可试 |
| ~~NanoBoyAdvance 1.8.3~~ | 已删除 | ❌ 本机加载 ROM 时崩溃（`0xc000041d`） |
| ~~SkyEmu v5~~ | 已删除 | ❌ 本机启动即崩溃（`0xc0000005`） |

> 后两个在整理磁盘时删掉了（占 62 MB 且在本机用不了）。
> 崩溃原因已排除 ROM 问题、运行库缺失、杀软注入、显卡不足
> （本机是 RTX 4070 Ti SUPER + Ryzen 9 7900X），属于系统环境层面的问题，
> 换台机器可能就正常；想再试可以直接重新下载（zip / 单文件，都不需要安装）。
> 日常试玩请用 mGBA：双击 `play.cmd` 即可。

| 工具 | 能力 | 备注 |
|---|---|---|
| **mGBA** | 日常试玩 + GDB 远程调试 | ✅ 已装好，双击 `play.cmd` |
| **mGBA + GDB** | 像调试 PC 程序一样调试 GBA：断点、单步、看变量、看内存 | 「工具 → 启动 GDB 服务器」；本工程编译时已带 `-g`，调试信息是现成的 |
| **no$gba** | 极强的调试器（内存查看、断点、VRAM 查看器） | 界面古老但功能最强，[官网](https://problemkaputt.de/gba.htm) |
| **屏幕打印** | 最土也最有效 | 配合 M2 的 TTE，把变量画到屏幕上 |
| VisualBoyAdvance | ❌ **不要用** | 早已停止维护，精度差，gbadev 官方明确不推荐 |

**mGBA + GDB 具体做法**（等你要用时再来找我配）：

```powershell
# 终端 1：让 mGBA 打开 ROM 并在 2345 端口等 GDB
& "C:\Program Files\mGBA\mGBA.exe" -g .\gba_ai.gba

# 终端 2：连上去
& .\.toolchain\arm-none-eabi-gcc\bin\arm-none-eabi-gdb.exe .\build\gba_ai.elf
(gdb) target remote localhost:2345
(gdb) break main
(gdb) continue
```

## 六、给你的建议（零基础起步）

1. **每次只改一点，跑起来看结果。** GBA 开发最快的进步方式是"高频小步"，
   不要一次写 300 行再编译。
2. **先做"能玩"的丑东西，再做"好看"。** 美术可以最后换，
   玩法验证才是核心。
3. **遇到崩溃先怀疑内存。** 32 KB IWRAM 很容易被一个手滑的大数组吃光。
4. **卡住时把错误信息原样发给我**（包括 `[build]`、`error:`、`[check]` 那几行），
   我能直接定位。
5. **想做什么类型的游戏先告诉我**，我可以把 M3~M5 的具体技术路线
   （tile 还是位图、要不要滚动、需要多少精灵）直接规划好。
