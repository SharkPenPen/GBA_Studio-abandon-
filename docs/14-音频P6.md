# 14 · 音频（P6）：语音 / BGM / 音效

P6 之前，引擎遇到语音、音乐、音效片段只能统计一下然后跳过。
现在这三类都能真的响了。

---

## 一、先讲清楚硬件限制

GBA 只有 **2 路 PCM**（Direct Sound A / B），外加 2 路老式波形通道。
所以"语音 + BGM + 音效同时响"在这台机器上**做不到**（除非自己写软件混音，
在 240×160 的机器上太奢侈）。本工程的分工：

| 通道 | 用途 |
|---|---|
| **DS A** | 语音（一次播完自动停） |
| **DS B** | BGM（循环）；**音效响起时抢占**，音效播完 BGM 从原位置接上 |

最常见的组合"语音 + BGM 同时响"是支持的（A、B 各一路）。
音效优先是因为它短，抢占听感上最自然。

**语音和 BGM 抢不到同一路**，所以编辑器里"语音重叠"是**硬错误**（不是警告）——
这在 P4 的合规检查里就拦住了。

## 二、数据管线

```
assets_src/audio 或任意位置的 *.wav
      ↓ tools/make_project_audio.py
8 位有符号 / 单声道 / 11025Hz 裸 PCM
      ↓
source/assets/aud_N.bin + snd_data.s（incbin）+ snd_table.c（表）
      ↓
CMD_VOICE / CMD_BGM / CMD_SE 用下标引用
```

**为什么是 8bit / 11kHz**：11 KB/秒。一句话 3 秒 = 33 KB，
一首 2 分钟 BGM = 1.3 MB。卡带最大 32 MB，采样率就是"音质 vs 容量"的直接取舍。
要更好的音质用 `--rate 22050`（翻倍），代价是容量翻倍。

转换会**自动归一化**（把峰值拉到 89%）：不同来源的素材音量参差不齐，
统一一下比在游戏里做音量控制省事。加 `--no-normalize` 可以关掉。

**OGG / MP3 不支持**：Python 标准库解不了。工具会**明确报错**并告诉你怎么做，
不做"静默跳过"——静默跳过最坑，做半天不知道为什么没声音。

## 三、怎么验证音频（我听不见，所以得用别的办法）

我没有耳朵，不能"试听一下"。能做的验证：

### 1. 静态：数据对不对

```
转换产物 aud_0.bin: 44100 字节
在 ROM 里的位置: 0x69760   ← 逐字节匹配 ✅
峰值 113/127，RMS 52.3     ← 不是静音 ✅
源 WAV 4.00 秒 → 转换后 4.00 秒 ✅
```

### 2. 动态：硬件寄存器真的被驱动了吗

mGBA 有 GDB 调试接口（`mGBA.exe -g`），但新版 `arm-none-eabi-gdb` 和它
**协议不兼容**（一上来就探测特性，mGBA 不答，握手超时）。
所以写了个最小客户端 `.tmp/read_regs.py`，直接用 GDB 远程协议的 `m` 包读内存。

实测读数（游戏跑到第一幕，BGM 应该在放）：

| 寄存器 | 读数 | 含义 |
|---|---|---|
| `s_bgm` | `0x0807B38C` | = `snd_clips[0]` 地址，引擎正在播这条 BGM |
| `s_bgm_playing` | `1` | 播放标志 |
| `SOUNDCNT_X` | `0x0080` | **总开关已开**（bit7） |
| `SOUNDCNT_H` | `0x300C` | **DS A/B 左右输出全开 + 100% 音量** |
| `TM1CNT` | `0x0080` | **BGM 定时器在跑** |
| `TM1D` | `0xFC34` | 落在 11025Hz 的重载区间（0xFA0E 起计数）里 |
| `s_frame` | `0x2AA` | 跑了 682 帧没崩 |

**结论：音频通道确实被正确打开并在运行。** 至于"好不好听"，
这就只能你自己戴上耳机听了。

> 说明一下我**没能**验证的：DMA 源地址寄存器读出来是 0。
> 这大概率是 mGBA 调试读取对 DMA 内部状态的实现问题
> （DMA1CNT/DMA2CNT 两个不同通道读出来一模一样，也说明这几个寄存器读不可靠），
> 但既然定时器在跑、通道已开、数据在 ROM 里且指针非空，音频路径是通的。
> **我不能保证音质，只能保证"通了"。**

## 四、踩的坑

### 1. 只生成声明没生成定义 → 链接失败

`make_project_audio.py` 一开始只写了 `extern const SndClip snd_clips[];`
（声明）和 `.s` 里的数据，**没写表的定义**。编译全过，链接报：

```
undefined reference to `snd_clips'
```

现在生成 `snd_table.c` 专门放定义；**没有音频时也生成一张空表** ——
引擎是无条件引用 `snd_clips_count` 的。

### 2. 缓存命中时返回值漏了包装

```python
# 错：命中缓存返回 int，调用方 "ix, why = ..." 直接炸
return v if isinstance(v, int) else (None, v)
# 对：两种情况都返回元组
return (v, None) if isinstance(v, int) else (None, v)
```

同一个 bug 在 P5 的 `sprite()` 里也潜伏着（当时每个角色只查一次所以没触发）。

### 3. GDB 一连上，mGBA 会把游戏复位

第一次读出来 `s_frame=0`、VCOUNT 不变、所有寄存器都是复位值 ——
**那是开机瞬间的状态**，不是运行中的状态。
正确流程是：连接 → 发 `c`(continue) 让它跑 → 过一会儿发 `0x03` 中断 → 再读。

差点据此得出"音频完全没工作"的错误结论。

### 4. 又一次 UTF-8 BOM

`edit` 工具改 `.ps1` 会**把 BOM 去掉**，PowerShell 5.1 随即把中文注释读成乱码、
解析器崩。本会话第三次了。已经把所有 `.ps1` 统一检查了一遍。
