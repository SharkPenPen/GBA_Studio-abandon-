# 特效与图层合成：能不能做、做到了什么程度

> 用户提了三件事：① 视频不要了 ② 特效能不能改成序列图 ③ 立绘能不能合成成一层
> 结论：**② 部分能（已经做了静态部分）③ 完全能（已经做了）** ✓

---

## 一、视频 —— 放弃 ✓

GBA 没有视频解码器 ✗ 逐帧转成位图的话体积会爆掉 ✓ 已确认放弃 ✓

---

## 二、特效：能做的和不能做的

### 原作的"特效"其实是两种东西

| 是什么 | 数量 | 能不能移植 |
|---|---|---|
| **`.fx` 文件** | 33 个 | ✗ **不能** —— 那是 DirectX 着色器源码（HLSL）<br>GBA 没有可编程管线，一行都用不了 |
| **`EFMSK_*.PNG` 蒙版** | 21 张 1280×720 | ✓ **能** —— 就是图片，按"正片叠底"叠上去即可 |
| **`EF03_W_003.png`** | 1 张 | ✓ 能（同上） |

`.fx` 里能看出原作用了哪些效果（`Noise` / `PP_ColorBloom` / `bltMask` / `FilmTex` …）✗
这些**效果的名字**是有用的 ✓ 但**实现**得在 GBA 上重做 ✓

### 已经做的：静态蒙版合成进去了

`tools/compose_scenes.py` 把 **底图 + 立绘 + 蒙版** 三层合成成**一张** 240×160 ✓
蒙版按正片叠底处理 ✗ 这是对 Darken / Mask 类特效最接近的近似 ✓

实测：全库 **180 种图层组合** ✓ 合成后 **13.2 MB** ✓（6 盘总容量 192 MB → 只占 **7%**）

### 还没做的：**动画**特效

像"噪点闪动""光芒扫过"这种**逐帧动画** ✗ 理论上可以做成**序列图** ✓
GBA 的精灵本来就是序列帧动画（引擎里 `anim_*` 已经支持 ✓）
**但现在拿不到帧序列** ✗✓ —— `.ws2` 里只有"用哪张蒙版" ✓ 没有"第几帧" ✓
帧序列在 `.fx` 的着色器参数和 Lua 里 ✓ 那两个都不好解析 ✓

**要做得靠手工** ✗ 但工程量不大：
1. 挑几个最显眼的效果（比如场景切换的白闪 ✓ 常用 ✓）
2. 用图片编辑器做 4~8 帧序列 ✓
3. 用引擎的动画系统播 ✓（`source/anim.c` 已就绪 ✓）

**要不要做，取决于你想要多接近原作** ✓ 不做也能玩 ✓ 只是少了点演出感 ✓

## 三、立绘合成：已经做了，而且发现它本来就不是问题

### 意外发现：这个游戏的立绘**本来就烘在大图里**

全库扫 511 个 `.ws2` 的图层使用：

```
图层名:  bg# ×759   ev# ×106   st# ×20     ← 立绘图层只用了 20 次
文件名:  BG 370  BGBLACK 215  BGWHITE 163  EV 104  EST 28
```

**`st#`（立绘图层）只出现 20 次** ✗ 而 `bg#`/`ev#`（整张背景/事件 CG）用了 865 次 ✓
→ **这个游戏的"立绘"是画在背景和 CG 里的** ✓（ADV 游戏常见做法 ✓）
→ 所以"立绘要不要单独合成"这件事**本来就几乎不存在** ✓

### 真正要合成的是"底图 + 蒙版"

```
180 种配方 = 底图 90 张 × 蒙版 20 种组合出来的
其中含独立立绘的配方只有 17 种
```

`tools/compose_scenes.py` 已经把它们全部合成成一层 ✓✓

### 实测（s1 章）

```
片段: text 579 / voice 151 / bg 50
合成背景: 43 张（多层已烘成一层）
导出清单: bg=43 sprites=0 audio=121
资源: 背景 3.15 MB + 音频 10.7 MB
ROM: 15.66 MB（占卡带 48.9%）
验证: 抓帧整帧 105 种颜色 ✓ 对话框文字 4924 像素 ✓
```

**一次合成，GBA 端零成本** ✗ 引擎不需要支持图层 ✓
（本来也支持不了 —— 模式 3/4/5 是位图模式，连图层都没有 ✓）

## 四、踩到的一个"静默失效"bug（值得记）

合成图**一张都挂不上**，而且**不报错** ✗ 查了半天：

```python
def _find_asset(proj, fname):
    want = fname.lower()                          # 'assets/bg/comp_xxx.png'
    if os.path.basename(a.path).lower() == want:  # 'comp_xxx.png'  ← 永远不相等 ✗
```

**拿 basename 去比完整相对路径** ✗
之所以一直没暴露：`.ws2` 传进来的是**裸文件名**（`BGBLACK.PNG` ✓）
那时 `want` 本身就是 basename ✓ 所以能对上 ✓
而预合成图给的是**工程内相对路径** ✓ 于是全部失配 ✓

**教训**：一个"凑巧能用"的比较 ✗ 会在换一种输入时静默失效 ✓
——两头都取 basename ✓ 并且把两种情况写进注释 ✓

## 五、还踩到一个更隐蔽的：消息编号不是同一套

TSV 的"索引"是**每个场景从 0 开始** ✓
而 `.ws2` 里的消息号是**全局编号**（`s1_01` 是 99~196 ✗）
两边条目数还不一样（127 vs 98 ✗）→ **按编号、按顺序都对不上** ✓

**解法：按日文原文的指纹对齐** ✗
两边都有同一句的日文原文 ✓ 归一化（去包装、去控制码、去空白）后取 MD5 ✓
实测 `s0_01` 两边指纹完全一致：`310b7da34e7e3e62` ✓✓

**这一条也顺带修好了语音和说话人的对齐** ✗
（它们原来对 `s0` 以外的场景**全是错的** ✓ 只是错得不明显 ✓
 —— 语音还是原作的语音 ✓ 只是配错了句子 ✓
 说话人更是会张冠李戴 ✓）
