# GBA 中文游戏工程

用 **C + libtonc** 做 GBA 游戏，配一个 **Python + Qt 的可视化编辑器**排剧情，
一条命令编出能在模拟器和实机上跑的 `.gba`。

**核心难点（GBA 不支持中文）已经解决**：按剧本按需生成 11×11 中文点阵字库
（源：中易宋体 12px 的内嵌点阵，再面积平均缩到 11px）。

**开发经过和踩过的坑都在 → [docs/00-开发日志.md](docs/00-开发日志.md)**
（每个阶段都写了"怎么验证的"；没有验证的结论不算结论）

## 三步开始

```powershell
# 1. 装工具链（只需一次，约 320 MB，校验官方 SHA256）
.\scripts\setup-toolchain-china.ps1

# 2. 编译
.\build.ps1

# 3. 编译并试玩
.\build.ps1 -Run
```

改了剧本或素材之后，先重新生成资源再编译（**顺序不能乱**：剧本 → 字库 → 图片/音频）：

```powershell
.\scripts\build-assets.ps1
.\build.ps1
```

> PowerShell 提示"禁止运行脚本"时，先执行一次：
> `Set-ExecutionPolicy -Scope Process Bypass`

## 两条使用路线

### 路线 A：用编辑器（推荐）

双击 **`启动编辑器.pyw`**，也可以：
（**打开的是项目列表**，双击某个项目才进编辑器 —— 界面参考 Pixel Game Maker MV。
　关掉编辑器会回到列表，所以"我有哪些项目"始终在第一屏。）

```powershell
python gbastudio\main.py            # 0.16 秒启动，调试时能看到报错

> **要用 OGG / MP3 音频？先跑一次解码库安装**
> ```
> python tools\setup-audio-codec.py
> ```
> 装完就能在编辑器里**直接导入 OGG/MP3/FLAC**，导出时**自动转码**成 GBA 格式
> （8 位单声道 PCM，默认 11025 Hz），不用先手工转 WAV。
> 装的东西放在项目自己的 `.tools/pylibs/`，换机器拷过去或重跑一次都行。
>
> 转码结果会**按源文件缓存**（`.tmp/audio-cache/`），重复导出不会重复解码。

> **双击时弹出"打开文件 - 安全警告"？**
> **实测结论（2026-10-10）：这台机器上双击 `.cmd` 会弹、双击 `.pyw` 不弹。**
> 所以入口统一用 `.pyw`（`启动编辑器.pyw`），项目里不再放 `.cmd`。
>
> 原因不是"文件来自 Internet" —— 用 Win32 的 `FindFirstStreamW` 扫过整个目录，
> **0 个文件带 `Zone.Identifier` 标记**。真正的原因是 Windows 把
> `.cmd/.bat/.exe` 这类**可执行文件类型**归到"不安全文件"名单里，
> 而这台机器的策略对它们**先问一句**；`.pyw` 不在那个名单里，所以不问。
>
> 要是以后还想用 `.cmd`：Internet 选项 → 安全 → Internet → 自定义级别 →
> 把「启动应用程序和不安全文件」改成"启用"（代价是这类文件不再询问就运行）。

启动是**空工程**（界面干净，不带示例素材）：把图片/音频拖进左边资源库，
点「＋台词」就能开始排。想看完整例子 →
菜单「文件 → 新建项目 → 示例剧情」，或直接打开
一个已有工程的 .gbastudio 文件（示例工程已经删掉，请用你自己的工程）。

编辑器里能做的：

| 功能 | 说明 |
|---|---|
| **时间轴排剧情** | 多轨道（同一类型可加多条）、拖片段移动、**拖边缘改长度**、吸附对齐 |
| **实时预览** | 中央的 240×160 画面**和实机逐像素一致**，按空格播放 |
| **资源库** | 导入素材（也支持拖放）、右键归类、资源在资源管理器里定位 |
| **属性** | 按属性注册表自动生成控件，改台词/表情/位置/时长 |
| **合规检查** | 编译前拦住 GBA 硬限制问题（语音重叠、台词超长、资源体积…） |
| **导出 GBA** | F5，后台编译，日志实时滚动 |
| **硬件精灵** | 关卡的角色由 GBA 的 OBJ 硬件合成（不占 CPU、不需要擦除）；128 个精灵、每行 32 个（P12）|
| **精灵动画** | 「精灵」模式里把帧连成动画（顺序/时长/循环），按 60 帧/秒实时预览；关卡里的角色用的就是它（P9）|
| **关卡模式** | 「关卡」模式里画笔刷图块（地板/墙/草/水）、右键设出生点；导出后实机就是能走能撞的地图（P8）|
| **界面字体可调** | 视图 → 界面字体（小/标准/大/特大），改完立刻生效并记住 |
| **面板自由缩放** | 拖分隔条随意改大小；预览可选「适应窗口」或固定倍数 |

### 界面操作

| 操作 | 效果 |
|---|---|
| 视图 → 界面字体 | 换字号。时间轴的行高列宽会**跟着变**，不会挤在一起 |
| 视图 → 重置面板布局 / Ctrl+0 | 面板拖乱了恢复默认 |
| 拖分隔条 | 面板随意放大缩小（没有人为设死的最小尺寸） |
| **Ctrl+滚轮** 放在预览上 | 缩放预览画面 |
| 预览缩放 → 适应窗口 | 面板多大就显示多大（自动取整数倍，像素不会大小不一） |
| 空格 | 播放/暂停 |
| Ctrl+滚轮 放在时间轴上 | 缩放时间轴

### 路线 B：直接改剧本

`scenario\scenario.txt` 是纯文本剧本，改完跑：

```powershell
.\scripts\build-assets.ps1 ; .\build.ps1 -Run
```

剧本格式（`#` 后面是注释）：

```
bg 0                # 背景：gfx_bgs[] 的下标
char 0 0            # 立绘：位置(0左/1中/2右) + gfx_sprites[] 下标
hide 2
say 魔女|海风停了。  # 名字为空 = 旁白
voice 1             # 语音（Direct Sound A）
bgm 0 loop          # 音乐（DS B，循环）
se 3                # 音效（抢占 B，播完把 BGM 接回原位置）
end
```

> 手写剧本也能用旧写法（`bg bg_ocean` / `char left witch`），解析器两种都认。

## 硬件限制备忘（做设计前先看）

| 项 | 上限 | 影响 |
|---|---|---|
| 屏幕 | 240×160，5 位色（每通道 32 级） | 背景要缩到 240×160；会有色带 |
| 内存 | IWRAM 32KB + EWRAM 256KB | 不能把大图放进内存 |
| 卡带 | 最大 32MB | 背景 76.8KB/张，音频 11KB/秒 |
| **PCM 通道** | **只有 2 路** | 语音+BGM 可以，加音效就要抢占 |
| OBJ 显存 | 32KB | **装不下大尺寸全彩立绘**（所以立绘用软件 blit） |
| 精灵数 | 128 个 / OBJ | 同上，本项目不用 OBJ |
| 单帧 | 280,896 周期 | 全屏重画约吃掉 60% 一帧 |

## 常见问题

**Q：改了台词，实机上有几个字是空白的？**
A：字库是按剧本收集字符生成的。改完剧本要重跑 `scripts\build-assets.ps1`。
   另外字库里如果有字渲染成空白，构建日志会明确列出（`⚠ 有 N 个字符渲染为空白`）。

**Q：导出的 ROM 没声音？**
A：检查音频格式 —— 转换工具**只认 WAV**。OGG/MP3 会明确报错并提示先转换。

**Q：编辑器打不开 / 双击没反应？**
A：用命令行跑 `python gbastudio\main.py`，报错会直接显示。
   注意 `.pyw` 的文件关联在有些机器上没注册，所以启动器用的是快捷方式。

**Q：立绘为什么不用硬件精灵（OBJ）？**
A：**立绘放不下**：OBJ 图块显存只有 32 KB，一张 111×120 的全彩立绘要 26 KB
   （位图模式下更只有 16 KB）。降到 16 色能放下但画面会毁掉 ——
   立绘继续用软件贴图，详见 [docs/13](docs/13-引擎升级P5.md)。

**Q：那什么地方用了硬件精灵？**
A：**关卡里的角色**。16×32 的小精灵只占 8 个图块（256 字节），
   128 个精灵、每行 32 个都绰绰有余，而且**六种显示模式通吃**。
   好处不只是省 CPU：**精灵不需要擦除**（浮在背景上，移开时背景本来就还在），
   软件贴图那种"走一路拖一串残影"的坑从此不存在。
   实现见 `source/obj.c`，排查记录见 [开发日志 P12](docs/00-开发日志.md)。

**Q：时间轴上看不到时间刻度，怎么对齐？**
A：**故意不画刻度**（秒数和"第几句"都不画）—— 片段自己就带着内容和名字，
   刻度既多余又要跟着对。对齐靠**吸附**：拖片段时会自动吸到其它片段的首尾，
   靠近就吸上，不用数格子。秒数只在右侧属性里作为次要信息出现
   （编译器和语音同步需要它）。
